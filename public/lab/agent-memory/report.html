Agent Memory：
从历史到未来决策

沿任务状态、事实证据和经验迁移三类需求，理解记忆方法的机制、关系与前沿。

状态 · 事实 · 经验
Agent Memory 研究的是：过去的信息，怎样持续改变后续决策？过去可以是几分钟前尚未完成的操作，也可以是跨会话更新的用户事实，或上百次任务积累的解决方法。不同时间关系，对应不同的记忆需求。本文从这些需求出发，解释方法为什么出现、彼此怎样衔接，以及实验已经支持了哪些认识。[53][45][46]

从同一个 Agent 的三种困难开始

设想一个持续维护代码项目的 Agent。它刚排查了一次超时：已经排除网络故障，正在检查接口版本与重试链路；项目最近又把默认接口从 v1 迁移到了 v2；几次相似故障后，它总结出一套检查超时预算的方法。这些历史都值得保留，但未来使用它们的方式不同。

同一任务继续执行

我做到哪一步了？

保留当前目标、约束、已确认结果和未完成事项。研究重点是：有限上下文中，哪些状态足以支撑下一步行动。

跨会话维持知识

现在应当相信什么？

保存用户、项目与环境的信息，让来源、生效时间和新旧版本保持可查。研究重点是：未来问题能否得到正确证据。

这些需求推动了哪些技术进展

以下进展跨越三类需求，解释方法之间的联系；正文仍按需求展开，再比较实现上的分歧。

历史的组织与访问。MemGPT 把持久记录与当前上下文分开；ReadAgent 用摘要定位并展开原文；A-MEM、HippoRAG 2、RMM 则在写入或检索时建立更有用的组织。这里的关键不是选中一种数据结构，而是把“怎样找到信息”和“用什么证据作答”连接起来。[6][54][12][11][15]

经验的抽象与迁移。Reflexion、ExpeL 和 ReasoningBank 研究反思与策略，AWM、Voyager 等工作研究流程和技能。它们共享从经历中抽象的目标，却依赖不同反馈、复用接口和验证方式。理解这些差异，才能判断一个系统究竟积累了知识、解决方法，还是新的可执行能力。[3][8][17][13][4]

管理过程的学习。当写入、检索、更新与调用都成为决策，研究便从设计固定规则扩展到训练策略、改写操作库和搜索架构。模型内部的隐状态与生成式记忆提供了另一种实现路径，也让记忆与学习的边界更加紧密。[58][21][22][65][66][67]

读完后应形成的四个判断

  1. 记忆用途先于架构名称。当前任务状态、跨会话事实和跨任务经验，所需保留的内容、允许的损失与有效性标准不同。
  2. 表示与读取共同决定收益。紧凑记录可以节省读取预算，可回溯原文则帮助恢复细节；合适的组织粒度依赖未来查询。
  3. 经验价值通过反馈和迁移显现。同题重试、未见任务首次尝试、跨模型迁移，对“学到了什么”提出不同要求。
  4. 效用是一条完整链路。信息存在、证据进入上下文、使用恰当、行动成功与长期成本，需要各自的测量。

这些判断由后续章节的机制比较与实验展开。正式论文、前沿预印本和生产资料承担不同证据角色；具体配置与数值核对放在相应展开区和来源页，便于顺着主线阅读，也便于回到细节。

CHAPTER 02 / 问题框架

先明确需求，
再比较记忆方法

建立统一的概念与决策框架，分清用途、载体、读写操作和学习方式。

一个可比较的 Agent Memory 系统，应明确三件事：历史要支持哪种未来决策，哪些信息会被保留，以及谁决定读写和更新。用途、载体和学习方式分别回答不同问题。先建立这套共同语言，后面的论文差异才有解释力。[53][45][46]
定义与边界三类需求两种循环分析坐标研究脉络

1. 记忆是历史与决策之间的中介

Agent 每一步接收观察，形成当前上下文，决定下一步回答或行动。把全部历史直接放进上下文，是最直接的保留方式；当交互增长，系统就要选择哪些内容留下、如何改写、何时取回。记忆系统由保存的状态和操作这些状态的过程共同组成：只描述数据库，无法解释系统什么时候会查；只描述提示词，也无法说明什么信息已经丢失。[53][45]

本文将 Agent Memory 理解为：Agent 在交互或任务经历中形成、维护并选择性访问的信息，以支持后续推理和行动。这个定义包含任务内工作状态、跨会话事实和跨任务经验，也允许外部记录与模型内部状态。它关注信息在时间上的延续，以及这种延续如何改变行为。

相邻概念与记忆的关系比较时需要补充的信息
上下文窗口当前一次模型计算可见的信息；可以包含取回的长期记忆。窗口外保留了什么？压缩后能否恢复原记录？
RAG把检索结果送给生成模型，是读取记忆的重要实现方式。原始 RAG 的知识来源主要是外部语料。检索库来自静态资料还是交互？有没有持续写入、纠错与经验抽象？[1]
会话持久化 / checkpoint恢复同一执行状态，支撑故障恢复和连续运行。是否会跨任务选择信息、更新语义事实或提炼方法？[47][52]
学习可以通过更新权重发生，也可以通过保存可重用知识、改写操作过程来发生。改变的是记忆内容、选择策略、可用操作，还是模型参数？[53]

更长的上下文扩大了当前可见空间；记忆管理决定如何使用这块空间。两者可以同时改进。类似地，技能文件既可能是人工编写的静态说明，也可能是经历验证后形成的产物；要判断它是否体现经验学习，需要追踪其形成、反馈和使用过程。

2. 三类需求构成稳定的研究主线

沿着首页的代码维护例子，可以把记忆需求放在三个问题下。它们不要求三个独立数据库，但需要不同的有效性标准。

需求保留对象有效性的核心判断主要研究路线
任务连续性当前目标、已完成步骤、工具返回、暂定假设、未解决约束。压缩与恢复后，是否仍能正确决定下一步？层级上下文、子目标摘要、可回读状态、受训状态更新。[6][54][14][28][29]
事实有效性用户偏好、实体关系、事件、项目约束与接口版本。能否找到与问题和时间一致的证据，并随着新信息修订？事实提取、主题组织、动态笔记、时序图谱、层次检索。[5][15][12][33][59]
经验可迁移性成败案例、条件化规则、工作流、代码与工具。在后续任务中能否改善判断或行动？哪些条件必须保持？反思、案例归纳、策略维护、工作流学习、技能验证。[3][8][17][13][4]

同一条记录可以承担多种角色。一次工具超时首先进入当前工作状态；其已确认原因可以成为项目事实；反复出现后，才可能支持一个诊断规则。记录从哪来，不决定它将怎样被使用。综述按主要用途展开，在方法跨界时说明连接关系。

与常用术语对齐：认知架构通常区分工作记忆、情节记忆（episodic）、语义记忆（semantic）和程序记忆（procedural）。CoALA 用它们描述当前工作状态、具体经历、事实知识与行动过程。本文的三类需求回答的是这些信息将支持什么决策：一份情节记录既能证明过去发生的事实，也能成为下一任务的参考案例；语义规则和程序技能也可共同支持经验迁移。因此，认知类型与用途分析可以对应，但不必一一绑定。[53]

3. 执行循环与改进循环

CoALA 将长期记忆读取、工作记忆中的推理、长期内容写入和外部行动分开，提供了清晰的决策视角。沿这个视角，Agent 一方面用已有记忆完成当前任务，另一方面根据新经历修改未来可用的信息或操作。[53]

当前可见信息 Cₜ = 任务状态 Wₜ + 按当前需求读取的 R(Mₜ, qₜ)
执行与观察 → 更新 Wₜ；可保留的经历 → 更新长期记忆 Mₜ
反馈评价 → 可选地改进读写规则、管理策略或模型参数

这里的 W 表示当前工作状态，M 表示持续保存的记录或内部记忆，R 表示读取过程。它们只是帮助对齐系统的符号，不要求某种固定架构。一次状态变化也未必构成强意义上的能力改进：写入“项目已采用 v2”使系统知识更新；训练一个更会选择证据的重排器，则改变了未来的读取行为。RMM 同时包含这两种变化，正适合作为跨界案例。[15]

“在线”和“离线”同样要相对于具体过程解释。LightMem 可以在线接收记录、后台整理；一个技能系统也可以离线优化候选，再在线执行冻结版本。讨论持续学习时，应说明哪部分随真实经历改变、哪部分依赖预先构造的训练集，以及评价发生在改变之前还是之后。[62][19][21]

4. 把正交维度放回各自的位置

确定需求之后，再用下表描述实现。这样既能识别方法群，也能比较跨越多个群的方法。

分析维度关键选择为什么有用
表示与载体原文、事实、图/树、指导文档、程序、隐状态或参数。决定信息如何编码、是否能回到原证据，以及可修改的单位。
组织与访问按主题或任务分块；向量/词法/图检索；固定一次或多轮回读。决定历史能否在有限预算内成为当前可用信息。
维护追加、合并、局部修订、失效、压缩、删除与回滚。决定新旧内容如何共存，以及错误会不会传播。
控制与学习固定规则、LLM 判断、反馈改写、策略训练、架构搜索。区分执行既定操作，与改变这些操作的决策规则。
主体与环境个人、项目、团队；文本、工具、图像、音视频和具身环境。决定谁产生与使用记忆，以及需要保持哪些身份和世界状态。

因此，“图记忆”“技能记忆”“强化学习记忆”和“神经记忆”并非同一层面的分类。图可以用于事实，也可以用于团队经验；技能可以是任务程序，也可以是管理记忆的操作；强化学习可以改进读取、写入或上下文更新；神经表示仍然需要容量与检索设计。后面的三章先讲用途，随后两章专门讨论管理学习与内部载体。[61][21][66]

5. 前沿从哪里生长出来

早期机制综述记录了外部存储、记忆操作与长期交互的基础问题；近期综述进一步纳入多种载体和学习方式。下面按代表性工作勾勒这些并行发展的线索。[44][45][46]

2023 年的 Generative Agents、MemGPT、Reflexion、Voyager 已分别展示观察与反思、层级上下文、失败经验和可执行技能。它们确立了一个共同方向：让 Agent 的行为依赖持久历史，而不只依赖当前输入。Generative Agents 的证据来自社会模拟中的行为可信度，Voyager 的证据来自 Minecraft 技能积累；这两种实验说明不同能力，不能合成一个通用记忆分数。[2][6][3][4]

2024—2025 年的一组代表性进展，集中于如何组织和恢复相关信息：ReadAgent 和 HiAgent 处理上下文粒度，HippoRAG 系列处理关联检索，A-MEM、RMM 处理动态组织与更新。LongMemEval 等评测又把索引、检索和读取拆开，让系统瓶颈可以分段研究。[54][14][10][11][12][15][35]

与此同时，2025—2026 年的工作进一步探索经验库、管理过程和内部表示的联合改进：ACE 与 ReasoningBank 改进经验内容，Memory-R1、MemSkill、MemEvolve 改进管理过程，M+、MemGen 探索模型内部的保留与使用。接下来需要回答的，是这些局部进展怎样组合成跨时间持续有效的系统。[18][17][58][21][22][66][67]

先从最接近每一次行动的问题开始：当整个历史已经放不进上下文，Agent 应当保留什么，才能继续完成当前任务？

CHAPTER 03 / 维持任务状态

历史放不下时，
怎样继续当前任务？

从层级上下文、可回读摘要与子目标状态，到受训的上下文管理。

工作记忆的目标，是让 Agent 在有限上下文中保住继续行动所需的状态。设想一个维护代码项目的 Agent：它已经排除了网络问题，发现接口版本不匹配，正在修改调用方。下一次调用最需要的是目标、已验证事实、当前改动和待检查事项；完整的搜索输出与失败日志则可以按需回看。本章用这个自拟场景串联研究，论文实验仍按各自的问答、规划和交互环境讨论。
从历史到状态压缩与回读按子目标组织学习状态更新设计选择

1. 从记录发生过什么，到表示下一步需要什么

逐轮拼接历史，是最直接的工作记忆实现。它保存了行动顺序，也保留了工具结果的细节；随着任务继续，模型需要从越来越长的文本中重新判断哪些信息仍然有效。代码 Agent 在第五轮读到的报错，可能已经被第十轮的修改修复。若两段输出都以相似权重留在提示中，后续推理就必须重复完成状态重建。

因此，这条研究线关心的是由历史形成当前状态：已经完成的目标、尚未解除的约束、支持判断的证据，以及下一步行动的依赖。所谓“充分状态”，是一个设计目标——在给定任务下，它应保留足以支持后续决策的信息。原始轨迹负责记录过程，当前状态负责组织行动，两者可以通过可回溯的引用连接。MemGPT、HiAgent 与 MEM1 分别把这一目标实现为可编辑工作区、子目标层级和迭代更新的文本状态。[6][14][28]

这里首先要区分两个时间尺度：当前排障任务的“已排除网络故障”属于任务内状态，而项目长期使用哪一版接口属于跨会话知识。前者随任务进度快速变化，后者需要版本和适用范围。本章先讨论前者，下一章再处理知识如何跨会话保持有效。

2. 压缩之后，怎样找回关键细节

MemGPT 的关键设计是分离持久记录与当前可见上下文。提示中包含系统指令、可编辑的工作区和滚动消息队列；外部存储保存历史对话及归档资料。当队列接近上限，系统发出容量提醒，Agent 可以转存重要信息，队列随后被压缩。历史消息仍在召回库中，Agent 通过搜索和分页把需要的部分重新放回上下文。容量管理由系统兜底，具体读写由模型的工具调用决定。[6]

ReadAgent 进一步回答“该回读哪里”。它先把长文档分成语义连贯的页面，为每页生成 gist，即保留叙事轮廓的简短表示。回答问题时，模型同时看到这些 gist，选择需要展开的页面，再用原文替换对应的摘要。这样，全局概览帮助定位，局部原文提供精确信息。与独立检索若干片段相比，这种设计尤其适合章节之间密切关联的故事、会议和长篇说明文档；它要求全部 gist 能放入工作区。[54]

两种方法的共同认识是：把细节移出上下文，应同时设计找回细节的路径。差别在于 MemGPT 面向持续到来的消息，自主决定何时搜索；ReadAgent 先读完整材料，再根据问题展开已建立的目录。在代码项目中，对应的工程选择可以是“记下文件和日志位置，需要时重新读取”，或“先建立模块概览，再展开相关实现”。

ReadAgent 的消融给出了直接证据：在 QuALITY 上，保留相同 gist、每次只取一页时，模型根据 gist 选择回读页面时，最终问答准确率为 84.13%；改用神经检索选择页面时为 82.65%。区别来自如何选择回读内容。更强压缩又会降低准确率，说明有目录和回读能力，仍需要目录保留足够的定位线索。[54]

3. 压缩单位为什么应当跟着任务结构走

面对行动轨迹，按固定消息数压缩容易切断一个尚未完成的子过程。代码 Agent 的“定位版本差异”可能只用两次读取，“验证所有调用方”却需要十余次搜索。HiAgent 让子目标成为记忆单元：执行当前子目标时保留完整 action-observation 序列；完成后生成一条包含结果的摘要，替换这段细节；后续需要追查时，再按子目标恢复原轨迹。压缩时机因此与任务进展对齐。[14]

这使记忆同时具有两个粒度。上层表示“已经做到什么”，下层保存“具体怎样做到”；尚未结束的子目标保留细节，因为后续动作往往仍依赖它。比起统一压缩率，更重要的是识别哪些信息已经可以折叠为稳定结果。若“单元测试通过”只覆盖部分模块，摘要就应保留测试范围，帮助下一轮继续验证。

HiAgent 专门比较了任务分解与记忆管理。在 Tyreworld 环境中，仅增加子目标规划、继续保留全部细节，成功率从 10% 提高到 40%；加入分层摘要与回读后达到 60%，同时降低上下文用量。这说明生成计划与管理计划执行后的信息，是互补的能力。另一组消融移除轨迹回读后，成功率从 60% 降到 50%，表明过去的执行细节仍有纠错价值。[14]

论文在 AgentBoard 的五种长程环境上评测，以 GPT-4 Turbo 同时执行行动生成和摘要，单任务上限为 30 步。上述数值来自 Tyreworld 的 Table 2–3；“仅任务分解”保留所有历史细节，完整 HiAgent 在该比较中的上下文用量为普通策略的 73.6%。Table 2 中无回读版本的进度率略高而成功率较低，因此应结合是否完成全部目标、步骤和成本阅读结果。

4. 从提示模型整理，到训练模型保留有用信息

提示驱动的方法把“如何记忆”写成规则。MEM1 则让模型在训练期间反复经历一种约束：每轮读取新观察、生成新的状态与行动，然后移除上一轮上下文。模型必须把未来有用的信息带入新的 <IS> 文本，才能获得任务奖励。这个状态同时包含对当前信息的归纳和下一步推理，压缩因此成为行动策略的一部分。[28]

MEM1 的训练环境把已有问答任务组合成多目标序列，要求 Agent 多轮检索后回答，并扩展到 WebShop 导航。论文用两目标组合训练，再评测更长、最多十六目标的组合，观察到状态管理能够推广到更长交互；这验证的是同类任务组成更长序列时的延续能力。它将“摘要读起来完整”改为“保留的信息是否支持最终完成任务”。近似恒定的上下文来自每轮裁剪与状态更新机制，奖励主要提供任务正确性的学习信号。[28]

MemAgent 采用相似的有限工作区约束，但对象是长文档证据流：顺序读取文本块，用普通 token 写出新记忆并覆盖旧记忆，读完后根据问题和最终记忆回答。训练通过多段独立上下文的强化学习，把最终答案的奖励传到中间记忆更新。与 MEM1 的交互式工具环境相比，它更集中地研究大量输入经过有限工作区后，还能留下多少回答依据。两者都把可读文本作为状态，模型内部的隐状态载体将在载体章另行分析。[29][28]

MemAgent 的消融显示：直接套用分块覆盖流程，在 LongBench-QA 上只有很小收益，部分设置下降；加入强化学习后才出现稳定改善。其证据位置实验还将关键内容放在开头、结尾或中部，检验后续覆盖是否冲掉前面的信息。这说明可扩展的循环框架只是第一步，保留哪些信息需要与任务反馈共同学习。[29]

展开：两种受训状态管理的协议差异

MEM1 从 Qwen2.5-7B Base 出发，以 PPO 训练，评估内部检索 QA、开放网络 QA 和 WebShop；训练和测试均使用会裁剪上下文的交互流程。MemAgent 采用 Qwen2.5 的 7B/14B Instruct 与 multi-conversation DAPO，默认记忆为 1,024 token、文本块为 5,000 token，在约 8K 工作窗口中顺序处理长输入。其超长输入结果主要回答长度外推问题；MEM1 的组合任务回答多轮交互外推问题。长度、目标数和环境变化应分别报告。

5. 在状态、回读与计算之间选择

上述工作形成了三种可组合的选择。对于细节随时可能再次变得重要的任务，采用 MemGPT、ReadAgent 式的可回读工作区；对于具有清楚阶段边界的任务，采用 HiAgent 式的子目标摘要；对于能够收集任务奖励、需要大量重复运行的环境，训练 MEM1、MemAgent 式的状态更新策略。实际系统可以先保留原始轨迹，再逐步学习把哪些信息常驻、哪些信息按需取回。

选择时，最值得测量的是同一任务在不同历史长度下的完成率、状态中关键约束的保留情况，以及回读带来的总成本。更短的提示有价值，是因为它减少重复处理并帮助行动；当恢复遗漏信息需要大量工具调用时，省下的 token 应与新增回读一起计量。学习过程如何获得可靠反馈，在记忆管理学习中继续展开。

工作状态随当前任务结束而完成使命，其中一部分信息却应继续服务下一次会话。例如，排障过程中确认的接口 v2 生效日期，值得进入项目知识库；“已经修改了两个调用方”则留在本次任务轨迹。接下来的问题是：这些被长期保留的事实，怎样组织、取证，并随项目变化及时修订。

CHAPTER 04 / 事实与证据

把长期历史，
变成可更新的证据

比较记忆单元、动态关联、时序与层次结构，理解写入和读取如何共同决定效果。

跨会话知识记忆，要同时提供容易找到的事实和能够追查的依据，并让它们随新信息保持有效。继续代码项目的自拟场景：Agent 上次记住“项目默认使用接口 v1”，本次发现 v2 已发布但部分服务仍在迁移。它需要知道这条规则适用于哪个服务、从何时生效、依据是什么；一个相似度很高的旧摘要，往往只解决了其中一部分问题。
证据与访问表示形成记忆单元建立关联维护有效性组织读取收益与成本

1. 原始证据与访问表示，承担两种职责

从历史对话、工具输出和文档中直接检索原始片段，是这条研究线的起点。原文保留了措辞、条件和上下文，但也包含重复表述、指代和交错主题。为了让未来的问题更容易找到答案，记忆系统会额外生成摘要、事实、实体关系和索引。这些派生表示的价值，是让原始信息更容易被寻址和组合。[1][15]

RMM 对这种分工给出了清楚实现：每个记忆条目保存 topic summary 与 raw dialogue，主题摘要作为检索键，关联的原始对话保留事实依据。会话结束后，系统抽取不同主题，对新旧相关记忆进行合并或追加；回答时检索主题，再使用关联内容。代码项目中，“接口鉴权方式”可以成为紧凑的访问入口，而具体版本限制仍应能回到对应文档和讨论。[15]

ReadAgent 的 gist 和 HippoRAG 2 的图也体现了相似分工：一个引导展开原始页面，一个引导选出原始段落。由此可见，重要的设计问题是派生表示如何指向证据。选择图、树或向量索引，应由实际查询决定：精确接口名需要词法匹配，跨模块依赖需要关联，历史版本问题需要时间范围。[54][11]

2. 先形成能独立理解的记忆单元

记录“这个已经改好了”几乎没有长期价值；记录“服务 A 的鉴权接口在 v2 中改用短期令牌”，才具有清楚主体和条件。SimpleMem 在写入时进行指代消解、相对日期规范化和事实拆分，再建立语义、关键词与结构化元数据索引。它还在当前会话内合并相关片段，让分散条件形成可共同读取的条目。例如，服务名、接口版本和迁移日期可以一起构成事实，而非分别等待读取阶段重新拼接。[57]

粒度应当与信息结构对齐。RMM 按主题抽取并关联原始对话；LightMem 在预压缩后按主题组织交互，用缓冲批量生成记忆；SimpleMem 从滑动窗口中提取能够独立解释的单元。它们分别强调跨轮主题完整性、构建吞吐与语义消歧。主题可以跨越多轮对话，一个会话也可以包含多个主题，固定 turn/session 边界因此只是输入边界。[15][62][57]

RMM 在随机抽取的 LongMemEval 样本上比较 turn、session、两者混合和主题组织，主题组织同时改善了检索与问答；简单混合不同粒度反而引入更多候选噪声。SimpleMem 的消融则显示，移除包含指代和时间规范化的语义压缩后，时间推理 F1 明显下降。两类证据共同支持一个认识：形成完整、可解释的信息单位，是有效压缩的重要条件。[15][57]

展开：粒度与消歧的实验依据

RMM §8.5 的粒度分析使用 100 个 LongMemEval 样本、GTE 检索器和 Gemini-1.5-Flash；其“最佳粒度”是每个样本从 turn/session 中选择较优者的参照。SimpleMem Table 5 使用 GPT-4.1-mini：移除整套语义压缩后，Temporal F1 从 58.62 降到 25.40。该移除同时改变抽取、消歧与表示，支持的是整套写入表示的作用。LightMem §5.4 的主题分段消融也显示，不分段略省计算，却降低下游 QA 准确率。

3. 关联用于写入理解，还是用于读取推理

当答案需要连接多条记录时，孤立条目的相似度检索开始受到限制。A-MEM 在新笔记到来时，先通过向量检索找到邻近旧笔记，再让 LLM 判断关系，并决定是否更新旧笔记的上下文描述、关键词和标签。新信息不仅增加一个节点，也改变旧信息的可解释方式。它适合说明写入时的整合：例如新迁移文档可能让早先的错误日志获得更明确的版本背景。[12]

HippoRAG 2 更集中于读取时的关联。它用抽取出的关系构建图，将原始 passage 也纳入图；问题先匹配关系三元组和段落，再用个性化 PageRank 沿关系传播，取出相关原文。早期 HippoRAG 主要以实体进入图，实体名可能省略问题中的条件。第二版增加 query-to-triple 和 passage 节点，让关系的语义与原文语境共同决定搜索方向。[10][11]

这个差异能被消融直接说明：HippoRAG 2 在三个多跳 QA 数据集上，完整方法的平均 passage Recall@5 为 87.1，移除 passage 节点后为 81.0；改回实体识别后匹配节点，降至 74.6。A-MEM 则在长期对话 QA 中发现，链接生成和已有笔记更新分别带来增益。前者说明图搜索需要保留语境，后者说明记忆进入系统时的整合有价值。两者的共同问题是：一条关系究竟帮助系统找到了哪些原本难以共同获得的证据。[11][12]

另一种关联是跨记录的层级概括。MemTree 在写入时沿语义相近的分支插入，并更新祖先摘要，让同一批记录同时具有细节与主题层表示。它的主要读取方式将各层节点放在一起按相似度选择，并非必须从根逐层走到叶子。相较于 HippoRAG 2 用图连接原始段落，树的价值在于形成多种概括粒度：问“这次调用失败在哪里”需要细节，问“项目迁移反复出现哪些问题”则可能需要跨记录的共同主题。组织结构与读取算法仍是两个独立选择。[59][11]

展开：如何阅读图方法的增益

HippoRAG 2 Table 4 的三组任务是 MuSiQue、2Wiki 和 HotpotQA，指标是原始段落召回；无候选过滤的平均值仍有 86.4，表明该实验中主要贡献来自上下文匹配和 passage 融合。A-MEM Table 3 在 GPT-4o-mini 上进行消融，移除链接与更新、仅移除更新、完整系统的 MultiHop F1 依次为 9.65、21.35、27.02。这些实验检验不同阶段和指标，适合解释机制，不宜排列为统一排名。

4. 让事实保持有效：时间、主体与证据身份

长期记忆还要表达变化。“接口 v2 从周一启用”可能周三才写入知识库；“项目已迁移”可能只适用于服务 A。查询当前状态、事故发生时的状态、当时系统已知的状态，分别需要不同时间和范围。Zep/Graphiti 将事实的有效时间与系统记录时间分开，保留实体关系及来源事件；新事实与旧关系发生时间重叠的冲突时，更新旧关系的失效时间，以同时支持当前查询和历史追溯。[33]

AriGraph 把更新问题放进可交互环境：用语义三元组表示当前世界，用情节节点保存当时的完整观察，新观察到来后修订失效关系。在文本化游戏中，“物品现在在哪里”更依赖语义状态，“配方具体怎么写”更依赖完整观察。它连接了任务内状态与可回溯事实，也说明保留历史不等于把所有历史状态都当成当前事实。[60]

Hindsight 进一步区分记录的语义身份：外部世界事实、Agent 自身经历、主观观点和由多条事实归纳出的实体概况。这个分工有助于解释为何“用户说服务 A 已升级”“Agent 建议升级”和“Agent 推测已升级”需要不同处理。它用实体与时间组织事实，多路检索后重排，再把证据交给回答与反思层。归纳概况可以提高读取效率，底层事实则提供追查和修订的依据。[56]

在 Zep 的 LongMemEval 结果中，时间推理、跨会话和偏好查询是收益较明显的类别；知识更新的收益又随回答模型变化。Hindsight 也在 LongMemEval 的时间、多会话和知识更新问题上报告较强表现。这些结果显示，结构化上下文能够帮助长期事实使用；它们同时提示，时间信息必须以回答模型能够正确使用的形式交付。工程中的版本过滤、冲突修订和来源追踪将在生产章继续落到具体约束。[33][56]

5. 从找到相似记录，到组成问题需要的证据

一次读取往往同时需要几种匹配能力：精确名称、语义近义、时间限制和关联实体。SimpleMem 根据问题生成语义、词法与结构化查询，动态决定读取范围，再对结果按条目身份去重；Hindsight 将多路检索、融合与神经重排组合，并允许调用者指定输出 token 预算与检索努力。这样，“查询一个接口名”和“解释三次版本迁移”可以获得不同的搜索深度。[57][56]

读取还可以从单次召回扩展为有目的的信息搜集：当前结果是否已覆盖问题的全部条件，是否需要补充时间、关联实体或原文细节，都可以成为下一次查询的依据。SimpleMem 移除意图感知读取后的下降，支持了根据问题组织证据的价值。让这种选择进一步随反馈适配，则进入管理学习的范围：RMM 训练轻量重排器，MemSifter 训练负责选择历史的代理模型。它们的监督来源与优化对象将在下一章组中比较。[57][15][68]

6. 构建记忆的价值，取决于预算和复用

复杂组织需要付出摄入、抽取和维护成本。LightMem 把同步更新改成先追加、后离线整理，并通过预压缩和主题缓冲减少构建调用；SimpleMem 在会话写入阶段即时合并相关事实。前者将更多整理工作移出在线路径，后者尽早压缩碎片。选择取决于新信息多久需要可见、同一份历史将被读取多少次，以及系统愿意为未来读取预先投入多少计算。[62][57]

LightMem 的独立复现提供了关键校准：固定构建后的记忆库和生成设置，更换检索器就会显著改变准确率；与直接检索原始用户 turn 比较时，构建记忆的优势主要出现在紧回答预算。约 330 token 的条件下，它在 11 个检索器中胜出 8 个，平均提高 5.5 个百分点；预算增到约 935 token 时，平均优势消失。紧凑条目让有限窗口容纳更多证据，但原文在预算充足时保留更多细节。[69]

因此，跨会话知识记忆应把写入表示、检索器、回答预算和维护成本一起设计。一套有解释力的比较，应同时保留强原文检索基线、构建表示，以及能够排除检索遗漏的证据条件。保留原始记录，再用摘要、关系和时间结构提供多种访问方式，是贯穿本章的系统思路。它让知识随着项目演进持续可用；当 Agent 进一步从多次排障中提炼“怎样更快定位版本问题”，研究对象就从事实延续转向了跨任务经验与技能。

CHAPTER 05 / 经验与技能

过去的经历，
怎样帮助新的任务？

案例、规则、工作流与程序的复用接口，以及反馈、维护和迁移的不同要求。

跨任务经验记忆要解决的，是让一次任务中付出的探索成本，在后续任务中继续产生价值。它可以保存具体案例、提炼决策规则，也可以留下工作流与可执行程序。这些形式各有用途：案例提供情境，规则帮助判断，程序承担重复执行。研究的关键，是解释经验怎样形成、经由什么接口改变行为，以及这种改变能迁移到哪里。
从重试到跨任务复用案例与规则反馈与归纳策略与程序持续积累迁移的条件

1. 同题反思与跨题学习：两个可以组合的回路

延续代码 Agent 的自拟例子：排障时发现“测试失败来自环境变量缺失”，可以立即修正环境再运行；也可以把诊断过程保存下来，供下次处理类似故障。前者改善本次尝试，后者改变未来任务的起点。记忆保存多久，不如它把哪次经验带给哪次决策更能说明学习发生在哪里。

Reflexion 将执行、评估和自我反思分开。执行者产生轨迹，评估器给出结果，反思器把结果与过程转成具体建议；下一次尝试同一任务时，建议与当前轨迹共同进入上下文。评估器可采用答案匹配、环境启发式或模型判断，记忆通常保留最近 1–3 次反思。这里语言建议承担的是稀疏反馈到下一次行动之间的桥梁。[3]

ExpeL 把桥梁延伸到未见任务：先在训练任务上借助重试收集经验，再从经验池提炼洞见、检索成功示例；测试时只尝试一次，也能利用先前练习。它因此把“练习时探索”与“执行时利用”分开。同题重试仍可叠加：论文在 ALFWorld 上观察到，ExpeL 的首次成功率为 59.0%，对未完成任务继续三轮反思后为 64.2%。这个组合说明，两种时间尺度可以同时贡献，而不是一条路线取代另一条。[8]

这种区分也决定怎样阅读实验：重试后的成功率衡量额外探索的效果，未见任务的首次成功率更直接反映经验迁移。比较方法时，应先确定经验来自训练集还是先前的测试任务，以及当前任务允许尝试几次，再讨论收益大小。

2. 案例与规则：保留情境，还是提炼共同结构？

具体案例保留问题、操作与环境的对应关系，适合回答“以前遇到相似情况时怎样处理”；一般规则则去掉实例细节，回答“这类情况应注意什么”。在代码排障中，完整调用链是一份案例，“先检查输入是否跨越协议边界”是一条策略。规则覆盖面可能更广，但案例能提供规则背后的条件，两者可以共同存在。

ExpeL 将两种对象放在同一系统中：按任务相似性检索成功轨迹作为示例；同时比较同题成功与失败轨迹，并从多题成功集合中抽取共同洞见。它不要求模型在“照着案例做”与“遵循一般原则”之间二选一。其消融提供了有解释力的差异：HotpotQA 更受益于洞见，ALFWorld 更受益于轨迹回忆，WebShop 则两者接近。有用的抽象粒度取决于任务需要重建什么。[8]

原文 §5.2：问答需要可跨问题使用的推理指引，具身任务有较稳定的动作结构，购物任务兼有检索、比较和执行。表格是特定实验中的对照，不是不同表示的普遍排名。完整 ExpeL 同时使用两条路径。[8]

这一选择也贯穿相关工作。Synapse 先抽象页面状态，再检索观察—行动轨迹；AWM 将完整经历切成参数化子流程；ReasoningBank 则保存高层策略。它们分别减少观察噪声、实例绑定与重复推导的负担。这里不宜画“轨迹越来越短，记忆越来越好”的上升阶梯：删除细节的同时，也可能删除未来任务需要的适用条件。[9][13][17]

Contextual Experience Replay 又区分了经验中的两类内容：环境知识记录常用页面、页面用途及 URL，操作模式描述反复有效的决策方法；系统分别提炼、保存并检索它们。这个划分提醒我们，一条看似通用的“经验”可能依赖网站的稳定 URL 或特定工具行为。经验抽象时保留这些环境条件，比单纯追求更短的规则更有助于迁移。[16]

3. 从结果到经验：反馈必须与归纳对象匹配

一次测试通过能证明特定检查成功，却不直接给出值得推广的规则；一次失败也可能同时包含正确步骤与错误假设。因此经验形成至少有两步：确定观察到的结果，再提出解释和可复用建议。Reflexion 把反馈转为下一轮行动建议，ExpeL 用成功与失败的对照支撑跨任务洞见，它们让归纳建立在可以检查的经历上。[3][8]

ReasoningBank 面向没有参考答案的任务流：任务完成后，由模型判定代理性的成功或失败，再分别抽取策略与教训，写成标题、描述和内容组成的条目；后续任务检索相关条目进入系统提示。其 MaTTS 将额外推理同时用于生产记忆：并行尝试之间可比较不同路径，连续修正则提供中间错误与调整过程。这样，额外计算的产物既可能改善当前答案，也可能成为未来任务的经验。[17]

ReasoningBank 在 WebArena-Shopping 的消融中，使用成功与失败经历比仅成功经历从 46.5 提高到 49.7；同一比较中，直接把失败纳入 AWM 则没有相同收益。其含义是失败能形成有价值的策略，但需要适合失败的转换过程。成功流程回答怎样完成任务，失败教训回答应避免什么、在哪一步增加检查；把两者原样混入同一个示例库，未必能利用这种差异。[17]

近期的 Trace2Skill 进一步让失败分析器检查产物、对照参考结果并尝试验证修复，再提出技能补丁；成功分析器则提取可复用行为。它将反馈来源从轨迹文字扩展到可检查的任务产物。相应地，在线自评和离线验证是不同的学习条件：前者便于持续积累，后者能够为候选修改提供更强的约束。选择取决于部署中能获得什么信号。[26]

展开：为什么不能把更多反思等同于更多证据

ExpeL §5.6 中，正常洞见提取在 HotpotQA 达到 39.0% 成功率，额外输入反思文本的变体为 29.0%。作者认为反思中的幻觉可能误导更高层归纳。这支持保留原始轨迹与归纳解释的区别；并不说明语言反思普遍无效。ReasoningBank 的 judge 也提供代理标签，当前版本对校准噪声做了实验，其结果仍须放在所测任务与噪声模型内理解。[8][17]

4. 策略、工作流与程序：谁负责重新生成行动？

当一个子过程反复出现，复用可以从“给建议”扩展到“执行已有实现”。两者的关键差异是接口：文字策略与示例进入模型上下文，由模型结合新状态产生行动；可执行函数则封装部分行动，可以被新程序组合调用。名为 skill 的文件既可能是前一种，也可能包含后一种，不能按名称归为同一种机制。

AWM 把“购买某种猫粮”的经历切出“搜索商品”子流程，并将具体商品替换为 {product-name}。每步包含环境描述、推理与行动，默认作为辅助上下文供 Agent 使用。Voyager 则把 Minecraft 技能存为可执行代码，按描述检索已有函数，用它们构造新程序；程序经过环境反馈、执行异常和成功自验证的迭代后进入技能库。前者减少每次寻找流程的负担，后者进一步支持程序组合。[13][4]

AWM 将工作流中的代码动作改为自然语言后，整体效果没有显示稳定的大差距。这说明真正重要的变量并不只是文字或代码的表面格式，而是子过程粒度、状态信息以及调用方式。代码 Agent 可以保留“先定位再修改”的文字策略，同时复用一个确定性的 trace 解析脚本；需要实时观察的决策仍由执行者完成。[13]

Mem²Evolve 将这种互补做成双存储：经验库记录工具使用、生成与调试的经验，资产库保存工具实现与专家 Agent 配置。执行时优先复用，缺少能力时用经验指导创建，随后验证并保存新资产。其 GAIA 分析中，经验指导使新工具首次通过系统内部验证的比例从 32.7% 到 51.0%，平均修正轮次从 1.45 到 0.94。这个中间结果清楚展示了经验如何帮助形成可用能力；资产质量仍受验证覆盖约束。[20]

5. 持续积累：维护执行知识，也保存改进历史

把一条经验提炼得好，只解决了第一次写入。随着任务增多，系统还要决定如何合并重复建议、局部修订旧规则，以及保留已经尝试过的修改。ACE 将执行、反思与维护分工：Generator 使用 playbook，Reflector 从轨迹提炼洞见，Curator 产生条目级修改，由确定性逻辑合并。增量更新配合去重，减少整份提示反复重写造成的知识丢失。[18]

技能文档的优化也体现同一问题。Trace2Skill 并行分析多条轨迹，再层次化合并补丁，突出跨经历重复出现的模式；SkillOpt 则控制每轮编辑数量，以选择集分数决定是否接受，并保留拒绝编辑与跨轮经验。一个偏向批量编译，一个偏向有界迭代；二者都把任务经历转换成部署时可直接使用的技能，而不是要求执行者阅读所有原始日志。[26][27]

Memento-Skills 和 EvoSkill 进一步把“怎样挑选候选”显式化。Memento-Skills 结合参考答案反馈、自产测试与回滚来修改技能，并训练查询到技能的路由；EvoSkill 通过失败分析提出新技能，按验证分数维护有限的 top-k 候选程序。这里形成两种不同的评估需求：候选本身是否改善留出任务，以及部署时能否正确触发它。只测全文注入后的效果，不能替代技能路由的检验。[24][25]

WikiSkill 明确分离了知识的消费者：原始层保存不可变轨迹，wiki 层积累模式、提案历史和影响记录，skill 层提供执行时的程序性指令。技能提案未通过验证时，skill 回滚，wiki 中的调查结果却保留。由此，记忆可以通过帮助优化器提出更好的修改产生价值，不必全部进入最终执行者的上下文。[19]

论文的 ALFWorld 案例展示了这个过程：泛化的“目标导向行动”提案未改善验证表现，系统保留拒绝记录；下一轮改为“不要把物品送回原位置”的具体规则后被接受，后续又根据新轨迹细化操作约束。配套消融中，给提案者加入持久 wiki 管线带来明显改善。这里的设计认识是：改进过程本身也需要连续性，部署指令则需要保持明确。[19]

展开：局部更新与持久知识的证据边界

ACE Appendix A.5 的 AppWorld test-normal 对照：非增量更新的 TGC/SGC 为 67.3/46.4，增量更新为 76.2/64.3。WikiSkill Table 3 在执行者不读 wiki 时，加入 Maintainer 与提案者 wiki 访问后，四基准平均分从 48.7 到 63.7；两项组件一起变化，不能将全部收益单归因于文件结构。WikiSkill 将技能全文注入系统提示，主要检验形成的技能质量，没有同时检验大规模技能触发与路由。[18][19]

6. 迁移取决于知识、消费者和执行环境

经验价值最终表现为后续任务行为的改变。应分别问：迁移的是具体经历、一般策略还是程序？目标任务是否共享工具和状态结构？目标模型是否能执行这些指导？一个文件能够被复制，并不意味着其中的假设能在目标环境成立。

ExpeL 将 HotpotQA 的洞见迁移到 FEVER，两者共享 Wikipedia 检索接口，并通过目标任务示例改写指导，取得正向迁移。WikiSkill 的跨模型结果揭示另一个侧面：小模型在 OfficeQA 形成的技能对自身帮助有限，却能改善更强模型的表现。发现可用程序知识和实际执行这种知识，是可以分离的能力。相反，为小模型设计的细碎 workaround 也可能妨碍强模型，或消耗更多交互预算。[8][19]

因此，经验研究已经形成的认识不是选出一种通用的最佳载体，而是让对象与复用方式匹配：相似情境保留案例，重复判断提炼规则，稳定子过程封装程序，反复优化保留提案历史。接下来的问题是，当这些对象都已存在，系统能否从反馈中学会更有效地选择、写入和维护它们？下一章讨论记忆管理本身的学习，将改变记忆内容与改变管理过程分开。

CHAPTER 06 / 记忆管理学习

让系统学会，
怎样记、怎样用

区分记忆内容变化、选择策略训练、操作库演化与架构搜索。

前面几章讨论保存哪些状态、事实与经验。本章改变一个问题：决定怎样读写这些记忆的过程，能否通过反馈改进？检索结果可以重新排序，写入动作可以训练，记忆操作规范可以演化，整套管理架构也可以搜索。它们是不同的优化位置，仍服务于任务连续性、事实有效性和经验迁移，而不是另外几种互斥的记忆用途。
内容与过程学习读取学习写入演化操作库搜索架构理解反馈与迁移

1. 更新记忆内容，与改进管理过程

代码 Agent 把“项目测试需要某个环境变量”写进记忆，是状态更新；从许多任务中学会“遇到新的环境配置，应检查旧记录是否仍有效”，则改变了写入规则。后一种变化有望作用于尚未出现的新记录。借用统一框架的区分，可以把二者写成：

Mt+1 = Uφ(Mt, 新观察)：在既定管理过程下更新记忆。
φ′ = Improve(φ, 执行反馈)：调整管理过程。
这是综述的统一记号。φ 可以指模型参数、操作说明或程序实现，不要求所有方法都使用梯度。

CoALA 将外部记忆与作用于记忆的操作分开，提供了理解这一差异的基础。固定的更新规则也能产生不断变化的记忆；相反，管理器经过训练后，可以在部署时冻结参数而继续写入新内容。因而“有写回”“使用强化学习”和“在线学习”描述的是不同性质。[53]

2. 学习读取：相似的记忆未必是实际有用的记忆

检索器找到与查询语义相近的内容，只完成了候选召回。代码 Agent 可能检索到许多含有“超时”的旧任务，其中只有一条涉及当前调用链与版本。学习读取的动机，是让选择过程适应特定任务和使用者，而不把通用语义相似度直接当作效用。

RMM 在固定检索器之后增加轻量重排器。它先取回 top-K 条目，再选择 top-M 给生成模型；生成模型在同一次调用中回答问题并标出使用了哪些记忆。被引用的条目得到 +1，未引用的得到 −1，REINFORCE 据此调整重排器。其前瞻反思另行把会话按连贯主题组织成“摘要＋原始片段”，学习排序与组织记忆因此成为两个可分开的机制。[15]

RMM 的训练信号是生成器的引用归因，不是答案正确性的奖励。这种信号容易在线获得，也不需要逐条人工相关性标注；它促使未来选择贴近生成器的实际使用。是否由此改善回答，仍需用独立任务指标判断。论文在 LongMemEval 的同设置消融中，单独加入回溯重排使准确率从 58.8 到 60.2，结合主题组织后为 61.2，支持两者在该条件下互补。[15]

Memory-R1 的读取端选择了另一种监督：先召回候选记忆，再训练 Answer Agent 过滤并推理，奖励来自与参考答案的 exact match。它更直接朝任务结果优化，但需要可核验答案。这两种方案最关键的分歧不是是否都使用 RL，而是反馈究竟奖励“模型使用了什么”还是“最后答对了什么”。[58]

MemSifter 更明确地把相对无记忆的结果增益用于选择训练：较小代理模型读取候选会话并思考排序，奖励比较无记忆与逐步增加 top-k 记忆后的回答得分，再按排名折扣。它将部分成本从提前构建复杂记忆，转移到查询时的代理推理；收益因此需要连同代理成本和最终执行器一起衡量。Memento 则以 soft Q-learning 建模案例选择；实际规划器采用无自举的单步 Q 函数，用即时成功信号训练，在这个实现中简化为监督学习，底层 LLM 保持冻结。两者把“选谁”与后续行为连接，选择单位分别偏向原始交互会话与任务经历。[68][23]

展开：RMM 的学习范围与代理奖励验证

ACL 2025 正式论文 Algorithm 1、§6：更新的是重排器，基础 retriever 与生成 LLM 冻结；默认从 20 条候选选 5 条。Table 2 使用 Contriever 与 Gemini-1.5-Flash：仅主题组织为 59.6%，仅回溯重排为 60.2%，完整 RMM 为 61.2%。§8.3 用另一个 LLM 判断所引记忆是否有用，与引用标签的一致性较高；这是代理信号的校验，不是移除记忆后重跑得到的因果效用。[15]

3. 学习写入：以未来回答约束当前更新

写入面临比排序更持久的选择：一条新信息应该新增、补充、替换还是忽略？简单的文字相似性难以分辨“第二个事实”与“对第一个事实的纠正”。一个项目新增测试入口，可能与原入口并存；若误删原记录，损失会在之后的任务才显现。

Memory-R1 将管理动作限定为 ADD、UPDATE、DELETE、NOOP，同时生成更新内容。训练时，Memory Manager 读取新信息与相关旧记忆，执行候选操作，再将更新后的记忆交给冻结的 Answer Agent；下游回答的正确性反馈用于优化管理策略。这样，选择 UPDATE 的理由不只来自一套提示规则，还受到后续问题是否能被回答的约束。[58]

论文中的例子是先收养 Buddy、后来又收养 Scout：两个名字代表可以共存的两次事件，而非后一条推翻前一条。训练后的管理器在所示案例中选择合并，保留两只狗的信息。这个机制揭示了写入学习的目标：保存对后续任务有用的区别，同时减少碎片与错误覆盖。它仍需要内容推理；选择了正确的操作名称，不保证生成的每个事实都正确。[58]

训练不需要人工给每一步管理动作贴标签，但使用了参考答案提供任务奖励。这种间接监督减少了操作标注工作，也带来信用分配问题：最终错误究竟来自没存、错删、没取到，还是回答者没理解？Memory-R1 将管理者与回答者分阶段训练，是在可控设置下处理耦合的一种方式。

4. 演化操作库：选择规则之外，还能改写规则

固定四种操作提供了清晰动作空间，却未说明应该怎样提取时间、保留事件角色或更新位置。不同领域反复需要的结构并不相同。MemSkill 因而把管理知识显式存成一组可选择的操作说明：初始只有 Insert、Update、Delete、Skip，随后允许细化并新增记忆技能。这里的技能指导如何构建记忆，与上一章用于完成外部任务的程序技能具有不同消费者。[21]

系统维护两类存储：每段对话或交互轨迹拥有自己的 memory bank，共享的 skill bank 则跨轨迹复用。Controller 根据当前文本片段和已检索旧记忆选择 top-K 技能，冻结的 LLM executor 在一次调用中按这些说明生成记忆更新。构建完成后的问题回答或任务成功率训练 controller；周期性 designer 从近期困难样本中归纳缺失行为，修改或扩展 skill bank。选择策略与操作定义交替改善。[21]

这使领域结构进入记忆构建过程。论文观察到，对话任务形成的技能更强调时间和活动细节，ALFWorld 技能更强调动作约束和物体位置。它不是简单要求“多记一点”，而是改变记录应保留的结构。同一章的消融也把贡献拆开：随机选择、固定初始操作、只允许改写不允许新增，均低于完整系统。这支持同时考察会不会选与有没有合适操作可选。[21]

展开：MemSkill 的两条优化回路与消融

§3.3–3.5：RL 更新 controller；executor 和 designer 的 LLM 固定，designer 修改的是技能文本。困难样本按查询记录预测、参考答案和相关记忆，经过聚类与难度选择后参与更新；系统保留较好技能库快照并可回滚。Table 2 的 LoCoMo judge score（LLaMA / Qwen）：完整系统 53.82 / 54.14，随机 controller 48.43 / 42.84，固定操作库 46.50 / 36.15，仅改写已有技能 47.45 / 48.88。这里检验的是相应任务上的管理行为学习。[21]

5. 搜索架构：把管理管线本身作为候选

即使动作选得正确，系统也可能因表示粒度、存储方式或检索路径不合适而受限。MemEvolve 将搜索范围放到更外层：以编码、存储、检索、维护四个模块构成设计空间，根据轨迹诊断瓶颈，再修改允许的实现位置，形成候选记忆系统。内层在给定架构下积累经验，外层比较候选并产生新的实现。[22]

它以任务表现、成本和延迟进行非支配排序，同级优先任务表现，再保留有限数量的候选。这与只训练一个排序器不同：优化产物是可以迁移的管理实现，也与不断向同一个库追加条目不同。论文将 TaskCraft 上演化的架构用于其他任务，并测试跨模型和框架迁移，提供了“管理设计可复用”的证据。[22]

因此，RMM、Memory-R1、MemSkill 与 MemEvolve 更适合放在同一张优化位置图，而非年代阶梯：若主要问题是候选选择，可只训练读取端；若长期损失来自写入，可学习操作；若领域需要新的记录规范，可演化操作库；若瓶颈跨越多个组件，则可搜索架构。更大的搜索范围意味着更多自由度，也意味着更多评估成本和归因工作。

展开：架构演化实验的实际规模

MemEvolve 实验的外层为 3 轮，每轮保留 1 个候选并产生 3 个后代；每个候选使用 60 条任务轨迹，其中 40 条新采样、20 条复用以稳定比较。架构候选的内层记忆在轮次开始时从空状态初始化。它是有明确预算的自动设计实验；跨任务测试迁移的是演化架构，不能解读为任意旧事实库可无条件迁移。[22]

6. 共同问题：用什么信号定义“更会管理”？

这些方法共享的目标，是让有限记忆资源更好地支持后续行为；差别在于用什么可观察信号逼近这一目标。引用奖励易获得，但会贴近生成器已有偏好；答案奖励更直接，却依赖可核验目标，并把多个步骤的影响压缩到最终结果；架构级多目标选择能计入资源代价，但需要对每个候选完成足够多的任务。这些是设计上的取舍，也是实验要回答的问题。

一个可解释的比较应固定历史、执行模型与任务预算，再分别检查管理变动及最终效果。还应明确迁移对象：把受训重排器给新用户、把记忆操作库给新领域、把架构给新框架，是不同承诺。训练时改过参数不意味着部署时还在在线学习；最终文档很短也不意味着形成它的计算很少。

管理学习使记忆从手工配置的组件，变成可以借助任务反馈调整的决策过程。当前证据已支持若干具体位置上的有效学习；下一步更重要的问题，是这些策略在更长时间、不同使用者与变化环境中能否继续保持效用。评测章将按这些条件审查结果；内部载体章则讨论另一条独立轴：记忆内容是否必须存为可读的外部记录。

CHAPTER 07 / 模型内部记忆

历史怎样进入
模型内部的计算？

从缓存和持久隐状态，到测试时快权重更新与生成式辅助记忆。

记忆载体的关键差别，是历史改变了模型计算中的哪个变量，以及后续怎样读取这个变化。前文的文本状态、事实库和技能主要通过提示进入模型；另一条研究线把历史保存在向量、隐状态或可更新的网络权重中。它们仍然服务任务延续、事实保留与经验迁移，只是写入和读取发生在不同层次。
什么发生变化保存过去的表示测试时更新权重生成辅助记忆组合与评估

1. 先问什么在变，再问是否属于神经记忆

同样叫“模型记住了”，可能对应不同过程。把旧文档放入提示，改变的是当前输入；把旧文档编码成向量并保存，改变的是可访问状态；根据新输入执行梯度更新，改变的是某个网络的权重；用受训模块生成一段辅助隐状态，改变的是本次推理过程。区分这些路径，才能判断一项能力来自当前证据、持久状态，还是训练经历。[7][65][30][67]

计算路径遇到新信息时写什么后续读取什么主要更新时间
固定权重＋外部上下文文本、事实、关系或程序装入提示的证据或工具结果交互写入、检索时装配
持久向量／隐状态KV、memory tokens、分层状态池检索到的向量或池中的表示新片段编码后更新状态
测试时快权重记忆网络的参数增量更新后的网络对查询的输出输入流上的在线学习
生成式辅助表示当前推理使用的 latent tokens这些 token 对后续生成的影响触发调用时生成；能力来自先前训练

“固定权重”描述模型参数在使用期间的状态；“外部存储”描述信息在哪里保存，两者并不排斥内部表示。LongMem 用固定骨干编码并缓存 KV，M+ 把长期隐状态放到 CPU 上，再检索回来参与模型计算。相反，MEM1 的状态写成普通文本，即使由强化学习训练出来，也仍可以直接读取其内容。载体、存储位置和训练方式应分别描述。[7][66][28]

2. 保存过去的向量：缓存、压缩与分层回读

LongMem 将“编码历史”和“使用历史”分开。冻结的骨干模型读取文本，产生注意力的 key-value 表示并写入缓存；可训练的 SideNet 根据当前 token 的查询，取回相关 KV，再与当前上下文共同计算。冻结编码器使旧缓存和新缓存处在一致的表示空间，SideNet 则学习怎样利用它们。缓存按序追加、容量满时淘汰最旧序列；实际取回以连续小块为单位，在检索开销和局部完整性之间选择。[7]

MemoryLLM 把更紧凑的状态池放到 Transformer 每一层。新文段与一部分已有 memory tokens 一起经过模型，产生新的状态，再替换池中的部分旧状态；生成时，当前输入通过注意力访问这些 memory tokens。这里的写入是前向计算形成新隐状态。模型先经过训练获得更新能力，使用新文段更新池时，主要变化的是保存的状态，而非再次完整微调骨干模型。固定容量也意味着旧信息会随更新逐渐减少。[65]

M+ 针对这一保留瓶颈增加第二级存储：原本会从短期池丢弃的 tokens 被转存到长期池，并记录年龄；生成时，共同训练的检索器取回相关长期 tokens，按时间顺序与短期池合并，再交给各层注意力。长期池放在 CPU，使较远历史的保存与 GPU 上即时参与计算的容量分开。这与文本记忆的“归档后按需回读”解决同一问题，只是回读对象变成了隐状态。[66]

MemoryLLM 与 M+ 的保留实验先注入回答所需文段，再连续注入其他文段，观察最初问题还能否回答。M+ 的分阶段比较显示，单纯延长训练上下文，对远处知识保留的改善有限；加入长期池及检索后，能够在更远的干扰位置恢复信息。由此得到的认识是：压缩容量与检索可达性必须共同设计，更大的训练窗口与可回读的长期存储承担不同作用。[65][66]

展开：M+ 保留实验的口径

M+ 使用 SQuAD 和 NaturalQA 构建先写入目标证据、再写入无关文段的序列。论文报告长期保留范围扩展至超过 160K 输入 token；§4.5 比较更新后的 MemoryLLM-8B、长上下文训练后的版本和最终 M+，并比较受训检索器与基于注意力的 KV 检索。这个长度描述插入目标证据后经过的输入规模；应连同保留曲线、模型和训练阶段理解。LongMem 的不同检索块大小消融则表明，在依赖精确标签的示例学习任务上，较细粒度读取更有利。

3. 把历史写进快权重：学习发生在测试期间

Titans 改变了写入对象。输入先被投影成 key 和 value，记忆模块是一个可更新的神经网络；系统计算它从 key 预测 value 的误差，再用该误差的梯度更新记忆网络。历史因此被编码进网络参数。读取时，当前输入产生 query，更新后的记忆网络直接输出相应表示，再与局部注意力结合。[30]

这里包含两个学习时间尺度。外层训练学习投影、控制和整个架构如何配合；测试输入到来时，内层仍更新记忆模块的快权重。Titans 加入动量，让近期的更新影响延续；加入由输入控制的衰减，调节旧记忆保留多少。论文另有一组称为 persistent memory 的参数，它们编码训练中形成的任务信息，在测试时保持固定。同一架构里的“持久参数”和“在线记忆权重”，其生命周期也不同。[30]

这一机制把“何时记住、何时淡化”的部分决策纳入连续计算。Titans 的组件消融同时考察语言建模、推理和长上下文任务；移除动量或遗忘机制都会降低结果，其中长期上下文指标的下降明显。它说明更新规则本身影响记忆的使用质量。对代码 Agent 而言，若采用类似路径，还需要明确状态何时随任务重置、是否跨项目保存；模型处理长序列的能力与这些产品级生命周期是两个相连的设计问题。[30]

4. 从训练经验生成记忆：辅助表示怎样介入推理

MemGen 处理的是另一种信息来源。它固定主要推理模型，训练 trigger 与 weaver：trigger 观察正在展开的推理，决定何时调用；weaver 依据当前隐藏状态，生成一小段 latent tokens，将其加入推理状态，引导后续 token 生成。训练经历被吸收到这些辅助模块的参数中，具体辅助表示则在每次调用时重新产生。[67]

这与前两条路径的差异在于当前取出的对象如何形成。MemoryLLM/M+ 保留输入历史形成的状态，Titans 更新一个用于关联查询的函数；MemGen 的 weaver 根据当前问题和推理状态生成辅助表示，可以表达从训练经验获得的做法。它把经验学习与生成计算连接起来，评价重点也转向新任务表现、调用时机和迁移，而非仅测某条原始事实保留了多久。[65][66][30][67]

MemGen 的触发消融提供了有解释力的比较：在 GPQA、KodCode 与 TriviaQA 上，训练出的 trigger 均优于随机插入，也优于每个句界都调用。以 TriviaQA 为例，每个句界调用为 64.15%，学习调用为 65.02%。收益说明何时增加辅助信息本身值得优化，而不只是增加更多生成 token。其更广泛实验还涉及 ALFWorld、数学和代码任务，覆盖的是从训练经历中迁移行为能力的研究方向。[67]

5. 混合使用载体，仍需要清楚的读写约定

回到三类记忆需求，代码 Agent 可以用文本状态延续排障，用带版本的外部记录保存项目事实，用训练出的策略或辅助表示改善诊断。内部表示为联合优化与计算压缩提供空间，外部记录为来源追查、显式修订和跨模型使用提供便利。一项技术的价值，应放在它承担的需求及整个读取流程中判断。

MemOS 提出的 MemCube 是这一方向的接口设计背景：尝试为参数、激活和明文记忆提供统一描述与生命周期管理。这里采用的是其统一资源抽象的设计主张。真正实现多载体协作，还需要具体规定一次写入改变哪个对象、关联哪些来源、由谁读取、何时过期，以及模型更新后旧表示是否仍兼容；这些约定能让不同记忆模块被替换和组合。[31]

因此，阅读内部记忆工作的结果时，应先确定“过去”指训练样本、同一输入流，还是跨会话保留的状态，再看测试是否真正要求使用它。保留曲线、问答准确率、任务成功率和推理成本分别反映不同能力。下一章将把这些需求与评测协议对齐，讨论怎样从实验结果判断记忆究竟改善了什么。

1. 先说明要证明哪一种记忆能力

贯穿本文的代码维护 Agent 会遇到三种不同测试：压缩长排障记录后，还能否接着验证未排除的假设；隔了几天，是否知道项目已经升级接口；处理一个新故障时，能否复用旧任务中学到的方法。这三题分别要求保持任务状态、更新知识和迁移经验。只问它“上次用了哪个命令”，无法替代三种测试；直接检查任务成功，又难以知道信息损失发生在哪一步。

前文的需求有鉴别力的协议需要观察的结果
任务连续在较早步骤引入后续才需要的约束；经过压缩或会话切换，再要求继续执行。中间状态是否保持、依赖深度增加时是否退化、出错后能否恢复。
事实有效顺序加入新事实、修正与时间信息；同时问当前值、历史值和无法回答的问题。证据保真、有效时间、更新传播和正确拒答，而非只看相关片段命中。
经验迁移从历史任务获得经验，冻结后测试未见任务；再比较允许持续更新的系统。迁移收益、负迁移、复用成本；与同题重试的收益分别报告。

对话 QA、行动测试与闭环执行因此是互补测量。LongMemEval 的索引—检索—读取分解适合定位事实处理；MemoryAgentBench 的增量摄入可以检查更新和全局理解；MemoryArena 让 Agent 自己的行动生成后续必须使用的状态。协议越接近完整执行，暴露的耦合越多，但也越需要局部实验帮助解释失败。[35][36][37]

还要明确“后续”是哪一种：同题重试、同一组合任务的下一会话、独立新任务，或环境变化后的新任务。MemoryArena 主要测组合任务内部的跨会话依赖；VibeMemBench 测选定仓库历史到后续目标的经验复用，但系统主实验在执行前一次注入；DolphinBench 则完整摄入用户历史后，再测模拟工具行动。它们都提供有价值的证据，支持的时间尺度不同。[37][40][39]

2. 现有实验带来了哪些可用认识？

表示应围绕需要保留的信息，而不是数据结构的名字

事实、摘要、原文各有收益。LongMemEval 表明，把长会话分解并用事实扩展检索键，可以突出线索；若直接用摘要或事实替代全部原文，又可能丢失细节。Execution Provenance 则发现，按源字段组织候选能改善预算内完整证据交付；固定候选后，图条件传播的额外收益集中在证据分散的查询。前者提示将索引抽象与证据回源结合，后者提示先检查记忆单元，再判断是否需要关系传播。该研究的候选视图同时改变字段范围，不能把全部收益归给切分或图。[35][42]

找到证据和用好证据，是两个可以分别改善的环节

LongMemEval 在提供正确证据的条件下，仍发现读取策略影响答案质量。MemCalib 进一步区分一条信息应被忽略、局部采用还是决定实质结论，并显示针对使用过度与使用不足的训练可以改善整体校准。这说明 reader 也是记忆系统的优化对象。它测的是已给定记忆对回答的影响，代码域也没有运行修复测试；其细粒度使用等级依赖评审规则，不能直接视为行动中的因果贡献。[35][41]

专门记忆能够改善某些困难任务，收益取决于系统组合

MemoryArena 在长轨迹搜索和形式推理上观察到外部记忆或检索的收益；在需要精确保留先前结果的任务中，较重抽象也未必优于原文检索。MemoryAgentBench 同样显示，稀疏信息定位和全局理解偏好的方案不同。这些结果给出了选择机制的条件，而不是通用架构排行榜。[37][36]

执行研究又补上了另一面：VibeMemBench 中，冻结经验的跨模型成功率提升仍有统计不确定性，多个系统并未稳定交付正收益；DolphinBench 的系统排序随模型和运行框架改变，准确率、延迟和总成本也可能向不同方向变化。较短轨迹不能单独证明记忆有效，更高分也需要说明为此付出的资源。[40][39]

3. 怎样设计有解释力的实验？

一个有说服力的实验先固定问题：同一任务、同一历史、同一执行器，只改变要检验的记忆环节。对照应从当前任务无历史开始，再加入可行的完整历史、等读取预算的简单原文检索和目标系统。若方法靠更多搜索、反思或技能生成获得优势，这些也是系统成本，需要明确计入。

用分层干预定位损失，而不是只做一次开关比较

固定什么、改变什么可以回答的问题
固定原始历史，比较不同写入与压缩；再提供原始历史中的必要证据。信息是否在入库时丢失？记忆条目能否回到依据？
固定记忆库和读取 token，比较实际检索与库内正确证据选择。库中已有内容是否被完整送达？额外结构改善的是表示还是排序？
固定提供的记忆，改变读取策略；分别加入无关、过时与矛盾内容。模型能否使用需要的信息，并限制不应影响当前任务的内容？
固定初始库，比较只读与允许更新；将历史和未来任务按时间严格隔离。持续维护是否优于静态库？收益来自迁移，还是看到了未来答案？

这些是综述建议的协议，不是已经运行的实验。正确证据必须来自当时真实存在且可访问的历史，不能把目标补丁、未来工具结果或完整解题计划作为“记忆”注入。原始证据有效、库内证据无效，提示写入损失；库内证据有效、实际检索无效，提示选择问题；正确证据仍无效，则应进一步检查任务可解性、读取与执行能力。LongMemEval 的 oracle 读取和 Provenance 的候选匹配对照说明，这样的分解能得到更具体的设计认识。[35][42]

对经验学习，另需固定历史轨迹与反馈来源，比较原轨迹、抽象经验和可执行技能，并留出任务簇。对持续更新，应在多个时间点评估，而不只看最终库。对隐状态与参数记忆，则须匹配训练数据和计算，避免把容量增加当成记忆机制收益。实验应跟随前文的主张，不能让所有路线只参加同一张 QA 榜。[3][17][30]

4. 把效果、预算与可靠性放在同一张账上

机制比较与资源比较回答不同问题。前者固定信息、执行器与读取预算，判断某种组织或使用方式是否有效；后者固定端到端费用或延迟上限，判断这笔资源投向记忆是否划算。等 top-k 不等于等 token，短提示也可能伴随昂贵的写入和反思。至少同时报告任务效果、写入与查询成本、端到端延迟，并区分一次性构建和持续维护。

每个成功任务的摊销成本 =
（写入 + 检索 + 推理 + 整理 + 验证 + 存储的总成本）÷ 成功任务数

DolphinBench 报告摄入加测试费用与测试延迟；MemoryAgentBench v4 已含成本和时间分析，但部分账目有缓存、定价与索引排除假设；VibeMemBench 的 solver tokens 和步骤不含记忆侧总账。比较结果前应对齐计费边界，再讨论质量—成本—延迟之间的取舍。[39][36][40]

重复运行同样重要。pass@k通常衡量多次尝试中至少一次成功，pass^k衡量全部尝试成功；前者说明重试潜力，后者更接近稳定性。给定 n 次运行中 c 次成功，随机抽取 k 次的估计分别为：

至少一次成功：1 − C(n−c, k) / C(n, k)
全部成功：C(c, k) / C(n, k)

应声明每次是否重置环境和记忆，并以任务、用户或仓库等独立单元做配对分析。完整 Agent 的失败还可能来自工具、规划或模拟用户，不能全归为记忆错误；轨迹诊断应同时检查这些来源。τ² 的具体环境案例收在附录。[40][38]

5. 下一步需要的是持续效用证据

当前最重要的空缺，是把已有局部进展连到长期净收益：随着任务增加，记忆能否保留适用条件、及时修正错误，并在未见任务和环境变化后继续有用？固定历史上的高分与组合任务内部的闭环已经提供必要测量，仍需补充持续摄入、任务交错、库增长和漂移的实验。[37][39][40]

评测还应保留不需要历史的自然任务，观察记忆是否带来干扰。经过“历史有效”筛选的数据适合研究系统为什么没用好经验，却不能估计日常任务中记忆需求有多频繁。研究结论因此应同时写明收益出现的条件、尚未区分的解释和长期验证范围；这也构成下一章生产系统持续评估的起点。[40][39]

版本比同名更重要。MemoryAgentBench 把 LongMemEval 改造为 5 段长对话、300 个问题的 LME(S*)，它不是原始 500 题评测。LoCoMo 旧 arXiv 摘要写平均 300 turns / 9k tokens，ACL 正式版 Table 1 则为 588.2 turns / 16,618.1 tokens；正式版 Table 5 的 1,986 个 QA 含 446 个 adversarial 问题，Mem0 的评测又排除了该题型。应冻结数据文件或 commit、问题集合、tokenizer、回答器、评判器及提示词。[36][35][34][32]

公平预算可以改变结论。MemoryAgentBench v4 Appendix J 在同一 GPT-4.1-mini 下，对 Banking77 的约 4k 处理-token 条件报告 BM25 83.0、长上下文 74.0；约 104k 条件下则为 88.0 与 93.0。该局部实验说明读取预算影响架构比较；两任务、有限预算档位不构成“某派容量一定更高”的普遍证明。其 Appendix I 已报告推理美元成本，但排除一次性嵌入索引并假设缓存、使用 2025-11 价格。不能把它误写成“从未报告成本”，也不能将其与完整生命周期总账直接等同。[36]

闭环难度应保留评分层级。MemoryArena 的 PS 是先算每任务通过的子任务比例、再按任务平均，sPS 进一步算约束满足比例；SR 在购物和规划要求最终整体满足约束，在渐进搜索和正式推理看最终子任务结果。把所有子任务摊平平均，或把局部进度当作完整任务成功，都会改变结论。[37]

Execution Provenance：候选视图、图残差与下游问答

Execution Provenance 把工具参数和输出转为与源坐标对齐的证据单元，在同一 2,048-token 预算下评估 Full Support：所有标注 gold spans 是否都被覆盖。正文 Table 2 中，Dense-FT 的 flat-512 为 53.71%，provenance-unit 为 72.78%，图条件残差 R-GCN 为 77.33%；前一差是 +19.07 个百分点，后一差是 +4.55 点，后者轨迹簇 bootstrap 95% CI 为 [2.98, 6.18]。[42]

真正有鉴别力的部分：保持候选与初始检索分数不变，图残差在直接召回只增加 0.19 点，在 453 个 multi-fact 查询上从 50.42% 到 62.25%。关系归一化、保持度数的随机边和关系移除控制说明观察到的收益依赖具体关系与端点，而不是随便增加一张共现图就有效。flat chunk-size 的四档逐指标 oracle 仍低于 provenance-unit 11.96 点，进一步排除“只要把平面片段切小”这一解释。

必须保留的限制：+19.07 点是整个候选视图的差，不是纯切分效应：flat 包括自由消息与推理，provenance 和 gold 范围只覆盖工具参数/输出。+4.55 点又包含训练过的残差模块，未与同参数非图 MLP 比较。315 条 linked+multi-fact 下游 QA 的 strict accuracy 为 71.75% → 77.78%，+6.03 点的区间 [0.00, 12.10] 触零，R-GCN 也未显著区别于 provenance-unit Dense-FT；这支持进一步研究，不能直接写成“图提升 Agent 成功率”。

MemCalib：原子使用等级、训练对照与评审边界

MemCalib 将每个原子命题的理想作用分为 Ignore（不影响当前答案）、Bound（局部支持）和 Control（决定实质结论或约束）。1,500 个测试请求直接带入记忆，以逐命题的过用/少用偏差构成样本校准分 SCS；Exact 是该回答内全部命题都用得恰当的比例，不是事实问答准确率。数据中 Ignore 占 84.3%，99.66% 的样本含有理想等级混合的块，故整块接受或拒绝会丢失粒度。[41]

MemCalib-RL 保持生成回答不变，删除指定奖励通道的原子命题，再做 teacher-forcing 比较 token 对数概率，用正负方向定位支持或抑制作用；它是信用分配的代理信号，不是重新运行任务得到的决策因果效应。Table 2 中 Qwen3-8B 的 GDPO → MemCalib-RL：SCS 72.25 → 79.54，Exact 57.91 → 67.89，报告为 3 seeds 均值；共同冷启动和留出验证集让这一训练对照有解释力。Table 3 的 token-absolute → token-ordered 也改善 SCS 4.84 点，支持方向信息的价值。

“综合更好”仍不等于每个错误都下降。Ministral 上 MemCalib-RL 的 sMUS 为 13.19，GRPO 为 5.73，代价换来较少过用。外部验证仅是 RPEval 的 150 个显式多偏好请求：Qwen3-8B 的整体逐偏好准确率改善，但使用不足 UPB 从 Base 的 3.53% 上升到 8.84%。Judge 的自然抽样一致率为 145/150＝96.7%，九类边界分层抽样为 111/150＝74.0%；不能只报前一个数字。这是校准训练的早期证据，尚未验证工具闭环或长期写回。

VibeMemBench：选择偏差、转移区间与记录归因

VibeMemBench 用参考模型 deepseek-v4-flash 筛选“注入某条历史经验优于无记忆”的目标：目标 gold patch 只进入离线相似修复筛选，蒸馏可见目标问题与历史轨迹/补丁，不能见目标 gold/test patch。参考条件 43.2% → 78.6% 是用于选择数据的审计结果，既受取最大候选的偏差也受随机种子噪声影响，不能当作无偏的记忆收益。随后把冻结经验交给 5 个留出模型，才是迁移测量。[40]

DolphinBench：任务验证、成本边界与配置比较

DolphinBench 不用“回忆我说过什么”来显式提示检索，而让历史决定动作细节。它用 GPT-5.6-Luna 对每个候选任务做 2 次相关原文 oracle、2 次无历史测试，要求前者全成功、后者全失败；最终 600 个任务以工具调用的确定性检查和语义 judge 共同评分，所有检查通过才成功。约 500k tokens 指每个人物的用户消息内容，不包括摄取过程中由被测 Agent 自己生成的回复。[39]

Table 2 同一 Hermes + GPT-5.6-Luna 组，内建记忆 → Mem0 的准确率为 65.67% → 70.67%，测试中位延迟 44.35 → 37.69 秒，摄取加测试总费用 $61.48 → $96.21。该例说明质量、时延、费用会朝不同方向变化；基线是内建记忆，不是无记忆。论文由 Mem0 作者发布，未给出该差值的置信区间，价格、harness、模型和适配实现需要冻结后独立核验。

三个合成人物、模拟应用、每任务 1–4 个评分动作、先完整摄取后测试，使它擅长诊断“知道何时用旧信息”，却不覆盖长流程依赖、在线持续更新、生产服务中断和他人并发修改。与 MemoryArena 的依赖子任务、VibeMemBench 的真实测试联合使用更合理；任何一项都不足以独占“生产级记忆评测”的名称。

展开案例：τ²-bench 的双控制环境、模拟器错误与版本核对

τ²-bench 的双控制设置可以用来说明双控制环境如何影响基准可靠性。传统设置中，Agent 操作工具，用户主要提供信息；τ²-bench 新 telecom 域允许用户操作自己的工具，例如关闭飞行模式或重启设备。两方通过沟通共同改变环境状态。[38]

CHAPTER 09 / 生产系统

把研究机制，
变成稳定的服务能力

明确状态、来源、更新可见性和生命周期，再逐步组合与验证记忆组件。

生产记忆系统的任务，是把研究中的“可用历史”变成稳定的服务约定。除了能否检索到信息，还要明确它属于谁、什么时候生效、从哪里产生、更新何时可见，以及出错后如何纠正。把这些约定建立在原始事件、派生记忆和当前上下文的分层上，才能逐步组合前面讨论的方法。
产品能力的位置分层与路径更新与一致性来源与生命周期验证与演进

1. 先确定需要哪一层能力

对代码维护 Agent 而言，恢复未完成的排障任务、记住项目默认接口、复用诊断脚本，是三种不同的服务需求。生产框架通常覆盖其中几层。选型应先把接口提供的能力映射到这些需求，再比较产品名称。

能力位置官方实现中的例子应用仍需定义的约定
恢复当前执行LangGraph 的 thread/checkpoint 持久化；OpenAI 的 conversation state 支持延续对话上下文。任务重置、工具幂等、环境状态是否仍与恢复点一致。[47][52]
维护 Agent 当前可用记忆Letta 的可编辑 memory blocks 与 MemFS/文件访问；上下文压缩、笔记和按需读取也属于这一层。哪些信息常驻，哪些按需取回；谁可编辑，以及如何验证更新。[48][51]
从交互形成跨会话内容Google Memory Bank 提供生成、检索及管理记忆的接口；AgentCore 区分短期事件与按策略提取的长期记忆。主体范围、提取策略、新旧事实关系、纠正和删除传播。[49][50]
检索资料与用户画像Supermemory 将文档索引、由内容形成的记忆、静态/动态画像分别暴露；profile 与针对当前问题的 search 承担不同职责。画像什么时候应注入、检索什么内容，以及生成完成后的可见性。[71]
语义记忆组件Mem0 的提取与更新、Zep/Graphiti 的时序关系、Hindsight 的记忆网络，为特定组织和读取方式提供实现参考。适配自身任务的效果、总费用、版本兼容和故障恢复。[32][33][56]

这个映射也解释了为什么“已经有持久化”之后仍可能需要记忆研究：持久化解决信息是否留存，语义组织与管理策略决定哪些信息会进入下一次决策。反过来，一个高质量事实库也无法自动恢复尚未完成的工具事务。

2. 原始事件、派生记忆、当前上下文

一个容易验证和演进的结构，是让原始事件保留证据，派生记忆组织解释，当前上下文服务行动。原始事件包括用户消息、工具参数/结果和外部文档版本；派生记忆包括摘要、事实、关系、策略与技能；每次执行再根据任务需求选择和装配。它与 ReadAgent 的摘要/原文、RMM 的主题键/对话证据、HippoRAG 2 的图/原始 passage 具有共同的分工。[54][15][11]

在线路径首先确定用户、项目与权限范围，再检索、重排并在预算内装配。面对“项目现在应使用哪个接口”，系统还要按有效期和当前版本筛选。与当前问题无关的个人画像、其他项目经验或已经失效的规则，不应仅因文本相似就进入上下文。

写入路径把新事件转为待检查的内容：它是一个观察、一个用户声明、一项已经验证的事实，还是 Agent 的推断？先记录语义身份和来源，再决定追加、合并或替代。后台路径承担较重的跨条目整理、冲突检测、经验归纳与技能验证；已有服务可持续使用已发布版本。

这种分层让算法替换变得可控：换检索器时保留同一记忆快照，换抽取方法时从同一原始事件重建，换技能版本时保留验证记录。这样才能把一次质量变化归因到具体环节，而不是把全部组件一起更新后只看最终分数。

3. 更新何时生效，是接口的一部分

LightMem 将重整工作延后，以降低在线写入负担；SimpleMem 在写入阶段做更多消歧与整合。生产中对应的是新鲜度、请求延迟和后台成本之间的选择。频繁变化的项目配置与稳定的用户偏好，可以采用不同策略。[62][57]

应区分三种完成状态：事件已持久化，文档已可检索，语义记忆或画像已更新。以 Supermemory 为例，文档 status=done 对应分块索引完成，默认的 dynamic dreaming 仍可能继续生成和更新记忆。一个等待索引完成后立即检查画像的用例，可能观测到不同步；这需要通过阶段状态、版本号或可见性承诺来处理。[71]

在接口迁移的例子里，9 月 20 日生效的 v2 公告可能在 9 月 21 日才被系统读入。查询“当时应该用什么”与“当时系统知道什么”需要不同时间。Zep 的时序设计提示我们区分事实生效与系统记录的时间；应用还要明确最新公告对旧规则的替代方式。[33]

需要记录的信息服务的判断
主体、项目、允许读取的范围谁可以使用这条记忆？权限变化后是否仍可读取？
原始来源、证据定位、生成方式这是已发生事实还是推断？纠错时应回到哪一段记录？
生效时间、记录时间、替代关系查询针对哪个时间？哪条版本当前有效？
派生关系、生成器/提示版本原始事实变化后，哪些摘要、图边和技能需要重建？
验证状态、使用记录、成本能否发布？后续是否带来收益或退化？

表中是信息需求，而非要求所有系统采用同一数据库模式。关键是让对外承诺能够被查询和验证；例如逻辑分组标签可以组织记忆，但应用授权仍须独立执行。

4. 让纠正与删除沿来源传播

长期记忆会把一次输入的影响带到未来。来源可靠性因此同时影响回答和后续学习。AgentPoison 研究通过污染知识或经验库触发行为偏移，MINJA 则研究攻击者通过交互影响写入过程。这两种路径分别对应“库中的内容被改动”和“正常摄取流程形成了不可信记忆”。[43][55]

对工程设计的启示，是保留内容与指令的边界：检索到的历史是带来源和适用条件的数据，调用工具、写入其他用户范围或发布技能仍由当前权限与控制过程决定。新推断和新技能可以先进入候选层，经验证后再提升为默认可用版本。

用户要求纠正一条事实时，不能只改显示出来的文本。由它形成的摘要、向量条目、图关系、画像和策略也可能继续影响结果。记录派生关系，可以把纠正转化为可执行的失效与重建任务；删除后再以检索和使用路径验证传播是否完成。对于模型参数或连续隐状态中的信息，可操作的修改单位不同，应另行定义保证。

展开：攻击研究的适用前提与检测取舍

AgentPoison 的攻击者能够向被检索的外部知识/经验库植入内容，其触发优化依赖具体检索条件。MINJA 的基线威胁模型使用跨用户共享记忆；该前提解释了攻击者对另一使用者的影响如何传递。用这些实验评估自身风险时，应先对齐写入入口、共享范围与后续读取条件。[43][55]

MINJA 的通用检测提示在 EHR-MIMIC 条件下检出 123/135 个攻击样本，同时把 34/50 个良性样本判成攻击。该结果说明只报告攻击检出率不足以决定是否适合服务真实流量。生命周期综述进一步把摄取、整理、检索和遗忘都纳入分析。[70]

5. 以可测量的能力逐步增加复杂度

实践中可以沿三类需求分别建立基线。当前任务先验证恢复与状态压缩，跨会话事实先比较原文检索和简单摘要，经验学习则从可追溯案例开始。只有定位到具体瓶颈后，再加入图关系、受训管理器或程序技能。这样得到的升级理由，是它解决了哪类失败，而不只是增加了模块。

一个诊断脚本的发布应带着输入范围、接口版本、成功条件、验证任务和回退方式。在目标任务之外的留出样本上验证，再观察真实使用中的调用率、错误类型和净收益。高复用场景可以摊销较大的整理成本；低复用或快速变化的场景，则可能更适合直接读取较新的原始证据。

把无记忆、等预算原文、当前方案和候选方案放在相同任务快照上比较，同时记录写入、检索、推理、整理和验证费用。研究论文提供机制与局部证据，官方文档提供能力约定；是否适合自己的长期任务流，最终由这套应用层评测回答。下一章进一步讨论：当记忆跨越团队、模态和不断变化的环境，哪些问题仍没有足够好的答案。

CHAPTER 10 / 前沿与开放问题

已经理解了什么，
下一步要解决什么？

从信息保留与经验迁移的矛盾，走向协作、多模态和长期自适应。

Agent Memory 的下一步，是把局部有效的机制接成能够持续积累价值的系统。任务状态、有效事实和可迁移经验已经有各自的设计与测量方法；当未来需求未知、参与者增加、观察跨越多种模态，或记忆不断增长时，这些机制会遇到共同的难题。本章从前文尚未接通的证据出发，提出五个具体研究问题。
未知未来与信息损失经验迁移与写入反馈协作记忆实体与世界状态长期收益与维护

近期总体综述分别从功能、载体、动态过程和记忆主体整理这个领域。它们共同提示：更丰富的数据结构、更主动的读写和更强的训练，可能在同一系统中组合。真正值得比较的是这些选择解决了哪种信息困难，又产生了什么新的代价；前文的三类需求为这种比较提供了起点。[45][46]

1. 未来需求未知时，怎样决定现在可以丢掉什么？

一个排障 Agent 今天只需要知道服务已经恢复，明天却可能被要求解释某次失败发生在哪个版本、由哪条工具结果证实。写入时若只保留“重启有效”，后续精确问题就失去了依据；若保存全部过程，又会增加检索、阅读和维护负担。任务内压缩、跨会话事实提取和经验抽象，都面对这种未来效用不确定性。

一条已有路径是把摘要作为入口，把细节留在可回读的来源中。ReadAgent 用 gist 定位原始页面，并在回答前展开需要的页面；RMM 用主题摘要帮助检索，以原始对话提供依据。LongMemEval 的实验也显示，压缩信息适合增强索引，而直接替代原文可能损失细节。这些结果支持“分层访问”，同时说明摘要质量不能只由语言是否流畅判断。[54][15][35]

仍未解决的是：摘要可能没有留下足以触发回读的线索，旧原文也可能因容量、权限或保留期限而不再可用。对反思和技能更难，因为丢掉的可能是规则成立的前提。一个在已知题型上有效的写入策略，并不自然保证未来问题改变后仍可恢复所需信息。

可推进认识的实验：先让系统在不知道后续题型的情况下处理同一段历史，再用留出的事实追问、状态恢复和策略迁移任务测试。分别比较只存抽象、抽象加回源、分层保留三种条件，固定读取预算并计入存储成本；额外检查失败是“细节已删除”还是“细节仍在但入口缺失”。这是综述建议的设计，可把信息保真问题与检索策略问题分开。

2. 未来任务的收益，怎样成为当前写入决策的反馈？

完成一次任务，并不能直接告诉系统哪条记忆值得留下。成功可能来自执行器已有能力，也可能依赖几条经验共同作用；一条有用建议被引用，并不说明它改变了结果。若把每次成功都蒸馏成通用规则，库会积累大量冗余甚至错误归因，而一条很久以后才有用的经验又可能过早被淘汰。

现有工作已让反馈进入不同环节。RMM 用回答中的引用信号调整检索排序；Memory-R1 让记忆管理器选择增、改、删或不操作，并根据更新后下游回答的正确性训练；ReasoningBank 从成功和失败轨迹中提取策略性记忆。它们分别使读取、维护和经验生成更具针对性，也揭示反馈的层次不同：被引用、当前答案正确和未来任务受益，尚不是同一个优化目标。[15][58][17]

VibeMemBench 进一步说明，一段经验的效果会随目标任务和执行器变化。由此需要回答的不是“如何生成更多教训”，而是如何识别适用范围，以及如何让后续使用结果修正原来的抽象。MemoryArena 的跨会话循环给出了连续使用的环境，但还需要把组合任务内的状态保持，与独立新任务上的策略迁移分别检验。[40][37]

可推进认识的实验：在冻结的历史任务上生成候选经验，记录来源、版本与适用条件，再将相同未来任务分别交给只读旧库和允许写入的系统；对部分候选做受控加入或移除，进行配对重复运行。按后续任务簇而非单次引用累计收益，并跟踪误用和修正。这个建议不假设一次移除就能给出精确因果归因，而是把长期信用分配变成可逐步检验的问题。

3. 多个 Agent 管理记忆，与团队拥有共同经验，有何不同？

当多个 Agent 参与同一系统，“多 Agent Memory”至少包含两件事。MIRIX 把不同记忆类型交给专门管理器，由 Meta Memory Manager 路由更新，Chat Agent 再按问题检索。这里首先改变的是维护工作的分工；它的截图问答和对话实验检验这种系统能否组织、交付信息，并不直接检验一个执行团队是否学会更好的协作。[63]

G-Memory 面对的是另一种对象：历史团队如何共同完成任务。它把交互片段、查询记录和抽象经验连成三层图，既提供高层指导，也为不同角色保留相关协作过程。原文的一个例子是求解 Agent 漏掉清洁步骤，由另一角色纠正；值得复用的不只是物品状态，还包括何时需要检查和干预。实验中移除高层经验或细粒度交互都会影响效果，支持两类信息共同保留的价值。[61]

这两种路径可以结合，但共享库正确不等于协作过程正确。团队还要处理重复写入、角色之间的不同观察、相互引用造成的错误强化，以及成员或分工改变后旧经验是否仍适用。G-Memory 的实现主要在新查询开始时提供记忆提示；现有结果尚不能替代成员动态变化、并发更新下的长期团队验证。[61][63]

可推进认识的实验：固定执行团队规模与总预算，分别改变管理器是否分工、共享内容是否包含协作经历；随后替换成员或交换角色。这样可以观察收益来自更好的存取服务，还是来自可迁移的协调知识。除任务成功率外，还应追踪纠错由谁发起、同一错误是否被多次确认，以及角色变化后的负迁移；这些是建议增加的测量，而非现有论文已经完成的证明。

4. 跨越图像、声音和时间，怎样保持同一个实体与变化的世界？

多模态记忆的困难不仅是把图片或语音转成文字。一个人换了衣服、同一个物品被移走、说话者暂时不在画面内，后续推理仍要知道哪些观察属于同一实体、哪一种状态现在有效。只保存“红衣男子拿着杯子”这样的局部描述，会把身份、观察和时间变化混在一起。

M3-Agent 用持久的 face/voice ID 将人物在不同片段中的观察连接起来，并把跨模态身份对应加入实体图；控制器通过多轮 node/clip search 组装回答依据。去掉身份关联或语义记忆会降低其视频问答表现，说明一致实体表示是可测的机制。MIRIX 则把截图内容提取到不同记忆类型，展示了另一条从原始感知流到结构化信息的路径。[64][63]

两者尚未解决全部世界状态问题。身份的高频关联可以帮助抵抗偶发识别错误，却不能直接作为“当前状态”的更新规则：一个杯子过去常在桌上，不能压过刚被移到柜中的新观察。M3-Agent 的错误分析也指出细节保留和空间推理困难。其 M3-Bench-robot 由佩戴头部设备的人类演员模拟机器人视角采集，评测仍以视频问答为主，不能据此声称已验证实体机器人的长期自主部署。[64]

可推进认识的实验：在连续观察中分别安排身份外观变化、物体位置变化、感知遮挡和错误关联，再测试恢复后的身份一致性与最新状态。固定感知模型，比较文字摘要、实体图和保留原始片段的混合方案；最后在可重置环境中检验这些状态是否改变行动成功率。这个建议将感知错误、记忆更新与行动效果连接起来，同时保留各环节的可解释性。

5. 怎样证明记忆积累的是长期收益，而不是维护负担？

记忆系统的收益和代价发生在不同时间。写入、归并、生成技能通常先花费资源，之后反复使用才可能回本；延后维护可以降低当前延迟，又可能延长旧事实被使用的时间。随着库增长，过去有价值的经验可能因接口变化而失效，后台整理也会引入新的错误。

LightMem 用主题化处理和 sleep-time update 将部分整理移出在线路径，明确探索写入效率与更新时机。它的独立复现又显示，构造记忆相对原始记录的优势随检索器和读取预算变化。DolphinBench 把摄入与测试成本纳入配置比较，但仍先完整摄入再测试；这些工作推进了成本测量，还需要与持续到来的任务、修正和删除连接。[62][69][39]

长期效用也要求保留错误修复能力。更新一条事实后，引用它的摘要、关系和技能是否同步变化；删除一条来源后，派生信息是否仍被使用；受到错误或恶意写入影响后，系统能否定位来源并回滚。这些问题把知识维护、经验迁移和生产治理接在一起，不能只以数据库中的记录已删除或当前测试通过来判断。[70][46]

可推进认识的实验：构造摄入与执行交错的时间序列，同时包含知识修正、工具版本变化和删除请求；从相同初始库比较不同维护频率与保留策略。持续报告相对无记忆基线的累计成功任务增量、总成本、过期信息生效时长和修复后的恢复速度，观察优势能否维持，以及需要多少复用才能摊平前期成本。这一设计可让“长期记忆”从容量描述，变成关于持续行为的可检验主张。
