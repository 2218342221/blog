CHAPTER 02 / 问题框架

先明确需求，
再比较记忆方法

建立统一的概念与决策框架，分清用途、载体、读写操作和学习方式。

状态 · 事实 · 经验
一个可比较的 Agent Memory 系统，应明确三件事：历史要支持哪种未来决策，哪些信息会被保留，以及谁决定读写和更新。用途、载体和学习方式分别回答不同问题。先建立这套共同语言，后面的论文差异才有解释力。[53][45][46]
定义与边界三类需求两种循环分析坐标研究脉络

1. 记忆是历史与决策之间的中介

Agent 每一步接收观察，形成当前上下文，决定下一步回答或行动。把全部历史直接放进上下文，是最直接的保留方式；当交互增长，系统就要选择哪些内容留下、如何改写、何时取回。记忆系统由保存的状态和操作这些状态的过程共同组成：只描述数据库，无法解释系统什么时候会查；只描述提示词，也无法说明什么信息已经丢失。[53][45]

本文将 Agent Memory 理解为：Agent 在交互或任务经历中形成、维护并选择性访问的信息，以支持后续推理和行动。这个定义包含任务内工作状态、跨会话事实和跨任务经验，也允许外部记录与模型内部状态。它关注信息在时间上的延续，以及这种延续如何改变行为。

相邻概念与记忆的关系比较时需要补充的信息
上下文窗口当前一次模型计算可见的信息；可以包含取回的长期记忆。窗口外保留了什么？压缩后能否恢复原记录？
RAG把检索结果送给生成模型，是读取记忆的重要实现方式。原始 RAG 的知识来源主要是外部语料。检索库来自静态资料还是交互？有没有持续写入、纠错与经验抽象？[1]
会话持久化 / checkpoint恢复同一执行状态，支撑故障恢复和连续运行。是否会跨任务选择信息、更新语义事实或提炼方法？[47][52]
学习可以通过更新权重发生，也可以通过保存可重用知识、改写操作过程来发生。改变的是记忆内容、选择策略、可用操作，还是模型参数？[53]

更长的上下文扩大了当前可见空间；记忆管理决定如何使用这块空间。两者可以同时改进。类似地，技能文件既可能是人工编写的静态说明，也可能是经历验证后形成的产物；要判断它是否体现经验学习，需要追踪其形成、反馈和使用过程。

2. 三类需求构成稳定的研究主线

沿着首页的代码维护例子，可以把记忆需求放在三个问题下。它们不要求三个独立数据库，但需要不同的有效性标准。

需求保留对象有效性的核心判断主要研究路线
任务连续性当前目标、已完成步骤、工具返回、暂定假设、未解决约束。压缩与恢复后，是否仍能正确决定下一步？层级上下文、子目标摘要、可回读状态、受训状态更新。[6][54][14][28][29]
事实有效性用户偏好、实体关系、事件、项目约束与接口版本。能否找到与问题和时间一致的证据，并随着新信息修订？事实提取、主题组织、动态笔记、时序图谱、层次检索。[5][15][12][33][59]
经验可迁移性成败案例、条件化规则、工作流、代码与工具。在后续任务中能否改善判断或行动？哪些条件必须保持？反思、案例归纳、策略维护、工作流学习、技能验证。[3][8][17][13][4]

同一条记录可以承担多种角色。一次工具超时首先进入当前工作状态；其已确认原因可以成为项目事实；反复出现后，才可能支持一个诊断规则。记录从哪来，不决定它将怎样被使用。综述按主要用途展开，在方法跨界时说明连接关系。

与常用术语对齐：认知架构通常区分工作记忆、情节记忆（episodic）、语义记忆（semantic）和程序记忆（procedural）。CoALA 用它们描述当前工作状态、具体经历、事实知识与行动过程。本文的三类需求回答的是这些信息将支持什么决策：一份情节记录既能证明过去发生的事实，也能成为下一任务的参考案例；语义规则和程序技能也可共同支持经验迁移。因此，认知类型与用途分析可以对应，但不必一一绑定。[53]

3. 执行循环与改进循环

CoALA 将长期记忆读取、工作记忆中的推理、长期内容写入和外部行动分开，提供了清晰的决策视角。沿这个视角，Agent 一方面用已有记忆完成当前任务，另一方面根据新经历修改未来可用的信息或操作。[53]

当前可见信息 Cₜ = 任务状态 Wₜ + 按当前需求读取的 R(Mₜ, qₜ)
执行与观察 → 更新 Wₜ；可保留的经历 → 更新长期记忆 Mₜ
反馈评价 → 可选地改进读写规则、管理策略或模型参数

这里的 W 表示当前工作状态，M 表示持续保存的记录或内部记忆，R 表示读取过程。它们只是帮助对齐系统的符号，不要求某种固定架构。一次状态变化也未必构成强意义上的能力改进：写入“项目已采用 v2”使系统知识更新；训练一个更会选择证据的重排器，则改变了未来的读取行为。RMM 同时包含这两种变化，正适合作为跨界案例。[15]

“在线”和“离线”同样要相对于具体过程解释。LightMem 可以在线接收记录、后台整理；一个技能系统也可以离线优化候选，再在线执行冻结版本。讨论持续学习时，应说明哪部分随真实经历改变、哪部分依赖预先构造的训练集，以及评价发生在改变之前还是之后。[62][19][21]

4. 把正交维度放回各自的位置

确定需求之后，再用下表描述实现。这样既能识别方法群，也能比较跨越多个群的方法。

分析维度关键选择为什么有用
表示与载体原文、事实、图/树、指导文档、程序、隐状态或参数。决定信息如何编码、是否能回到原证据，以及可修改的单位。
组织与访问按主题或任务分块；向量/词法/图检索；固定一次或多轮回读。决定历史能否在有限预算内成为当前可用信息。
维护追加、合并、局部修订、失效、压缩、删除与回滚。决定新旧内容如何共存，以及错误会不会传播。
控制与学习固定规则、LLM 判断、反馈改写、策略训练、架构搜索。区分执行既定操作，与改变这些操作的决策规则。
主体与环境个人、项目、团队；文本、工具、图像、音视频和具身环境。决定谁产生与使用记忆，以及需要保持哪些身份和世界状态。

因此，“图记忆”“技能记忆”“强化学习记忆”和“神经记忆”并非同一层面的分类。图可以用于事实，也可以用于团队经验；技能可以是任务程序，也可以是管理记忆的操作；强化学习可以改进读取、写入或上下文更新；神经表示仍然需要容量与检索设计。后面的三章先讲用途，随后两章专门讨论管理学习与内部载体。[61][21][66]

5. 前沿从哪里生长出来

早期机制综述记录了外部存储、记忆操作与长期交互的基础问题；近期综述进一步纳入多种载体和学习方式。下面按代表性工作勾勒这些并行发展的线索。[44][45][46]

2023 年的 Generative Agents、MemGPT、Reflexion、Voyager 已分别展示观察与反思、层级上下文、失败经验和可执行技能。它们确立了一个共同方向：让 Agent 的行为依赖持久历史，而不只依赖当前输入。Generative Agents 的证据来自社会模拟中的行为可信度，Voyager 的证据来自 Minecraft 技能积累；这两种实验说明不同能力，不能合成一个通用记忆分数。[2][6][3][4]

2024—2025 年的一组代表性进展，集中于如何组织和恢复相关信息：ReadAgent 和 HiAgent 处理上下文粒度，HippoRAG 系列处理关联检索，A-MEM、RMM 处理动态组织与更新。LongMemEval 等评测又把索引、检索和读取拆开，让系统瓶颈可以分段研究。[54][14][10][11][12][15][35]

与此同时，2025—2026 年的工作进一步探索经验库、管理过程和内部表示的联合改进：ACE 与 ReasoningBank 改进经验内容，Memory-R1、MemSkill、MemEvolve 改进管理过程，M+、MemGen 探索模型内部的保留与使用。接下来需要回答的，是这些局部进展怎样组合成跨时间持续有效的系统。[18][17][58][21][22][66][67]

先从最接近每一次行动的问题开始：当整个历史已经放不进上下文，Agent 应当保留什么，才能继续完成当前任务？
