第 06 章 · 记忆管理学习本地阅读

CHAPTER 06 / 记忆管理学习

让系统学会，
怎样记、怎样用

区分记忆内容变化、选择策略训练、操作库演化与架构搜索。

状态 · 事实 · 经验
前面几章讨论保存哪些状态、事实与经验。本章改变一个问题：决定怎样读写这些记忆的过程，能否通过反馈改进？检索结果可以重新排序，写入动作可以训练，记忆操作规范可以演化，整套管理架构也可以搜索。它们是不同的优化位置，仍服务于任务连续性、事实有效性和经验迁移，而不是另外几种互斥的记忆用途。
内容与过程学习读取学习写入演化操作库搜索架构理解反馈与迁移

1. 更新记忆内容，与改进管理过程

代码 Agent 把“项目测试需要某个环境变量”写进记忆，是状态更新；从许多任务中学会“遇到新的环境配置，应检查旧记录是否仍有效”，则改变了写入规则。后一种变化有望作用于尚未出现的新记录。借用统一框架的区分，可以把二者写成：

Mt+1 = Uφ(Mt, 新观察)：在既定管理过程下更新记忆。
φ′ = Improve(φ, 执行反馈)：调整管理过程。
这是综述的统一记号。φ 可以指模型参数、操作说明或程序实现，不要求所有方法都使用梯度。

CoALA 将外部记忆与作用于记忆的操作分开，提供了理解这一差异的基础。固定的更新规则也能产生不断变化的记忆；相反，管理器经过训练后，可以在部署时冻结参数而继续写入新内容。因而“有写回”“使用强化学习”和“在线学习”描述的是不同性质。[53]

2. 学习读取：相似的记忆未必是实际有用的记忆

检索器找到与查询语义相近的内容，只完成了候选召回。代码 Agent 可能检索到许多含有“超时”的旧任务，其中只有一条涉及当前调用链与版本。学习读取的动机，是让选择过程适应特定任务和使用者，而不把通用语义相似度直接当作效用。

RMM 在固定检索器之后增加轻量重排器。它先取回 top-K 条目，再选择 top-M 给生成模型；生成模型在同一次调用中回答问题并标出使用了哪些记忆。被引用的条目得到 +1，未引用的得到 −1，REINFORCE 据此调整重排器。其前瞻反思另行把会话按连贯主题组织成“摘要＋原始片段”，学习排序与组织记忆因此成为两个可分开的机制。[15]

RMM 的训练信号是生成器的引用归因，不是答案正确性的奖励。这种信号容易在线获得，也不需要逐条人工相关性标注；它促使未来选择贴近生成器的实际使用。是否由此改善回答，仍需用独立任务指标判断。论文在 LongMemEval 的同设置消融中，单独加入回溯重排使准确率从 58.8 到 60.2，结合主题组织后为 61.2，支持两者在该条件下互补。[15]

Memory-R1 的读取端选择了另一种监督：先召回候选记忆，再训练 Answer Agent 过滤并推理，奖励来自与参考答案的 exact match。它更直接朝任务结果优化，但需要可核验答案。这两种方案最关键的分歧不是是否都使用 RL，而是反馈究竟奖励“模型使用了什么”还是“最后答对了什么”。[58]

MemSifter 更明确地把相对无记忆的结果增益用于选择训练：较小代理模型读取候选会话并思考排序，奖励比较无记忆与逐步增加 top-k 记忆后的回答得分，再按排名折扣。它将部分成本从提前构建复杂记忆，转移到查询时的代理推理；收益因此需要连同代理成本和最终执行器一起衡量。Memento 则以 soft Q-learning 建模案例选择；实际规划器采用无自举的单步 Q 函数，用即时成功信号训练，在这个实现中简化为监督学习，底层 LLM 保持冻结。两者把“选谁”与后续行为连接，选择单位分别偏向原始交互会话与任务经历。[68][23]

展开：RMM 的学习范围与代理奖励验证

ACL 2025 正式论文 Algorithm 1、§6：更新的是重排器，基础 retriever 与生成 LLM 冻结；默认从 20 条候选选 5 条。Table 2 使用 Contriever 与 Gemini-1.5-Flash：仅主题组织为 59.6%，仅回溯重排为 60.2%，完整 RMM 为 61.2%。§8.3 用另一个 LLM 判断所引记忆是否有用，与引用标签的一致性较高；这是代理信号的校验，不是移除记忆后重跑得到的因果效用。[15]

3. 学习写入：以未来回答约束当前更新

写入面临比排序更持久的选择：一条新信息应该新增、补充、替换还是忽略？简单的文字相似性难以分辨“第二个事实”与“对第一个事实的纠正”。一个项目新增测试入口，可能与原入口并存；若误删原记录，损失会在之后的任务才显现。

Memory-R1 将管理动作限定为 ADD、UPDATE、DELETE、NOOP，同时生成更新内容。训练时，Memory Manager 读取新信息与相关旧记忆，执行候选操作，再将更新后的记忆交给冻结的 Answer Agent；下游回答的正确性反馈用于优化管理策略。这样，选择 UPDATE 的理由不只来自一套提示规则，还受到后续问题是否能被回答的约束。[58]

论文中的例子是先收养 Buddy、后来又收养 Scout：两个名字代表可以共存的两次事件，而非后一条推翻前一条。训练后的管理器在所示案例中选择合并，保留两只狗的信息。这个机制揭示了写入学习的目标：保存对后续任务有用的区别，同时减少碎片与错误覆盖。它仍需要内容推理；选择了正确的操作名称，不保证生成的每个事实都正确。[58]

训练不需要人工给每一步管理动作贴标签，但使用了参考答案提供任务奖励。这种间接监督减少了操作标注工作，也带来信用分配问题：最终错误究竟来自没存、错删、没取到，还是回答者没理解？Memory-R1 将管理者与回答者分阶段训练，是在可控设置下处理耦合的一种方式。

4. 演化操作库：选择规则之外，还能改写规则

固定四种操作提供了清晰动作空间，却未说明应该怎样提取时间、保留事件角色或更新位置。不同领域反复需要的结构并不相同。MemSkill 因而把管理知识显式存成一组可选择的操作说明：初始只有 Insert、Update、Delete、Skip，随后允许细化并新增记忆技能。这里的技能指导如何构建记忆，与上一章用于完成外部任务的程序技能具有不同消费者。[21]

系统维护两类存储：每段对话或交互轨迹拥有自己的 memory bank，共享的 skill bank 则跨轨迹复用。Controller 根据当前文本片段和已检索旧记忆选择 top-K 技能，冻结的 LLM executor 在一次调用中按这些说明生成记忆更新。构建完成后的问题回答或任务成功率训练 controller；周期性 designer 从近期困难样本中归纳缺失行为，修改或扩展 skill bank。选择策略与操作定义交替改善。[21]

这使领域结构进入记忆构建过程。论文观察到，对话任务形成的技能更强调时间和活动细节，ALFWorld 技能更强调动作约束和物体位置。它不是简单要求“多记一点”，而是改变记录应保留的结构。同一章的消融也把贡献拆开：随机选择、固定初始操作、只允许改写不允许新增，均低于完整系统。这支持同时考察会不会选与有没有合适操作可选。[21]

展开：MemSkill 的两条优化回路与消融

§3.3–3.5：RL 更新 controller；executor 和 designer 的 LLM 固定，designer 修改的是技能文本。困难样本按查询记录预测、参考答案和相关记忆，经过聚类与难度选择后参与更新；系统保留较好技能库快照并可回滚。Table 2 的 LoCoMo judge score（LLaMA / Qwen）：完整系统 53.82 / 54.14，随机 controller 48.43 / 42.84，固定操作库 46.50 / 36.15，仅改写已有技能 47.45 / 48.88。这里检验的是相应任务上的管理行为学习。[21]

5. 搜索架构：把管理管线本身作为候选

即使动作选得正确，系统也可能因表示粒度、存储方式或检索路径不合适而受限。MemEvolve 将搜索范围放到更外层：以编码、存储、检索、维护四个模块构成设计空间，根据轨迹诊断瓶颈，再修改允许的实现位置，形成候选记忆系统。内层在给定架构下积累经验，外层比较候选并产生新的实现。[22]

它以任务表现、成本和延迟进行非支配排序，同级优先任务表现，再保留有限数量的候选。这与只训练一个排序器不同：优化产物是可以迁移的管理实现，也与不断向同一个库追加条目不同。论文将 TaskCraft 上演化的架构用于其他任务，并测试跨模型和框架迁移，提供了“管理设计可复用”的证据。[22]

因此，RMM、Memory-R1、MemSkill 与 MemEvolve 更适合放在同一张优化位置图，而非年代阶梯：若主要问题是候选选择，可只训练读取端；若长期损失来自写入，可学习操作；若领域需要新的记录规范，可演化操作库；若瓶颈跨越多个组件，则可搜索架构。更大的搜索范围意味着更多自由度，也意味着更多评估成本和归因工作。

展开：架构演化实验的实际规模

MemEvolve 实验的外层为 3 轮，每轮保留 1 个候选并产生 3 个后代；每个候选使用 60 条任务轨迹，其中 40 条新采样、20 条复用以稳定比较。架构候选的内层记忆在轮次开始时从空状态初始化。它是有明确预算的自动设计实验；跨任务测试迁移的是演化架构，不能解读为任意旧事实库可无条件迁移。[22]

6. 共同问题：用什么信号定义“更会管理”？

这些方法共享的目标，是让有限记忆资源更好地支持后续行为；差别在于用什么可观察信号逼近这一目标。引用奖励易获得，但会贴近生成器已有偏好；答案奖励更直接，却依赖可核验目标，并把多个步骤的影响压缩到最终结果；架构级多目标选择能计入资源代价，但需要对每个候选完成足够多的任务。这些是设计上的取舍，也是实验要回答的问题。

一个可解释的比较应固定历史、执行模型与任务预算，再分别检查管理变动及最终效果。还应明确迁移对象：把受训重排器给新用户、把记忆操作库给新领域、把架构给新框架，是不同承诺。训练时改过参数不意味着部署时还在在线学习；最终文档很短也不意味着形成它的计算很少。

管理学习使记忆从手工配置的组件，变成可以借助任务反馈调整的决策过程。当前证据已支持若干具体位置上的有效学习；下一步更重要的问题，是这些策略在更长时间、不同使用者与变化环境中能否继续保持效用。评测章将按这些条件审查结果；内部载体章则讨论另一条独立轴：记忆内容是否必须存为可读的外部记录。
