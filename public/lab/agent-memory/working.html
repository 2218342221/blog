CHAPTER 03 / 维持任务状态

历史放不下时，
怎样继续当前任务？

从层级上下文、可回读摘要与子目标状态，到受训的上下文管理。

状态 · 事实 · 经验
工作记忆的目标，是让 Agent 在有限上下文中保住继续行动所需的状态。设想一个维护代码项目的 Agent：它已经排除了网络问题，发现接口版本不匹配，正在修改调用方。下一次调用最需要的是目标、已验证事实、当前改动和待检查事项；完整的搜索输出与失败日志则可以按需回看。本章用这个自拟场景串联研究，论文实验仍按各自的问答、规划和交互环境讨论。
从历史到状态压缩与回读按子目标组织学习状态更新设计选择

1. 从记录发生过什么，到表示下一步需要什么

逐轮拼接历史，是最直接的工作记忆实现。它保存了行动顺序，也保留了工具结果的细节；随着任务继续，模型需要从越来越长的文本中重新判断哪些信息仍然有效。代码 Agent 在第五轮读到的报错，可能已经被第十轮的修改修复。若两段输出都以相似权重留在提示中，后续推理就必须重复完成状态重建。

因此，这条研究线关心的是由历史形成当前状态：已经完成的目标、尚未解除的约束、支持判断的证据，以及下一步行动的依赖。所谓“充分状态”，是一个设计目标——在给定任务下，它应保留足以支持后续决策的信息。原始轨迹负责记录过程，当前状态负责组织行动，两者可以通过可回溯的引用连接。MemGPT、HiAgent 与 MEM1 分别把这一目标实现为可编辑工作区、子目标层级和迭代更新的文本状态。[6][14][28]

这里首先要区分两个时间尺度：当前排障任务的“已排除网络故障”属于任务内状态，而项目长期使用哪一版接口属于跨会话知识。前者随任务进度快速变化，后者需要版本和适用范围。本章先讨论前者，下一章再处理知识如何跨会话保持有效。

2. 压缩之后，怎样找回关键细节

MemGPT 的关键设计是分离持久记录与当前可见上下文。提示中包含系统指令、可编辑的工作区和滚动消息队列；外部存储保存历史对话及归档资料。当队列接近上限，系统发出容量提醒，Agent 可以转存重要信息，队列随后被压缩。历史消息仍在召回库中，Agent 通过搜索和分页把需要的部分重新放回上下文。容量管理由系统兜底，具体读写由模型的工具调用决定。[6]

ReadAgent 进一步回答“该回读哪里”。它先把长文档分成语义连贯的页面，为每页生成 gist，即保留叙事轮廓的简短表示。回答问题时，模型同时看到这些 gist，选择需要展开的页面，再用原文替换对应的摘要。这样，全局概览帮助定位，局部原文提供精确信息。与独立检索若干片段相比，这种设计尤其适合章节之间密切关联的故事、会议和长篇说明文档；它要求全部 gist 能放入工作区。[54]

两种方法的共同认识是：把细节移出上下文，应同时设计找回细节的路径。差别在于 MemGPT 面向持续到来的消息，自主决定何时搜索；ReadAgent 先读完整材料，再根据问题展开已建立的目录。在代码项目中，对应的工程选择可以是“记下文件和日志位置，需要时重新读取”，或“先建立模块概览，再展开相关实现”。

ReadAgent 的消融给出了直接证据：在 QuALITY 上，保留相同 gist、每次只取一页时，模型根据 gist 选择回读页面时，最终问答准确率为 84.13%；改用神经检索选择页面时为 82.65%。区别来自如何选择回读内容。更强压缩又会降低准确率，说明有目录和回读能力，仍需要目录保留足够的定位线索。[54]

展开：回读实验与成本如何理解

ReadAgent §4.4 的 Table 4 比较上述两种单页读取策略；Table 6 将页面上限从 400 增至 1,200 词，gist-only 准确率从 78.91% 降至 73.97%，允许回读的版本从 86.82% 降至 85.67%。回读缓解了压缩损失。§3.3 同时计入分页、生成 gist、回读和回答成本：预处理开销可由同一文档上的多个问题分摊。MemGPT 的 DMR 则测跨会话事实问答，其摘要基线与保留完整历史的分页搜索系统可获得的信息不同；它展示完整存储和回读的系统价值。

3. 压缩单位为什么应当跟着任务结构走

面对行动轨迹，按固定消息数压缩容易切断一个尚未完成的子过程。代码 Agent 的“定位版本差异”可能只用两次读取，“验证所有调用方”却需要十余次搜索。HiAgent 让子目标成为记忆单元：执行当前子目标时保留完整 action-observation 序列；完成后生成一条包含结果的摘要，替换这段细节；后续需要追查时，再按子目标恢复原轨迹。压缩时机因此与任务进展对齐。[14]

这使记忆同时具有两个粒度。上层表示“已经做到什么”，下层保存“具体怎样做到”；尚未结束的子目标保留细节，因为后续动作往往仍依赖它。比起统一压缩率，更重要的是识别哪些信息已经可以折叠为稳定结果。若“单元测试通过”只覆盖部分模块，摘要就应保留测试范围，帮助下一轮继续验证。

HiAgent 专门比较了任务分解与记忆管理。在 Tyreworld 环境中，仅增加子目标规划、继续保留全部细节，成功率从 10% 提高到 40%；加入分层摘要与回读后达到 60%，同时降低上下文用量。这说明生成计划与管理计划执行后的信息，是互补的能力。另一组消融移除轨迹回读后，成功率从 60% 降到 50%，表明过去的执行细节仍有纠错价值。[14]

4. 从提示模型整理，到训练模型保留有用信息

提示驱动的方法把“如何记忆”写成规则。MEM1 则让模型在训练期间反复经历一种约束：每轮读取新观察、生成新的状态与行动，然后移除上一轮上下文。模型必须把未来有用的信息带入新的 <IS> 文本，才能获得任务奖励。这个状态同时包含对当前信息的归纳和下一步推理，压缩因此成为行动策略的一部分。[28]

MEM1 的训练环境把已有问答任务组合成多目标序列，要求 Agent 多轮检索后回答，并扩展到 WebShop 导航。论文用两目标组合训练，再评测更长、最多十六目标的组合，观察到状态管理能够推广到更长交互；这验证的是同类任务组成更长序列时的延续能力。它将“摘要读起来完整”改为“保留的信息是否支持最终完成任务”。近似恒定的上下文来自每轮裁剪与状态更新机制，奖励主要提供任务正确性的学习信号。[28]

MemAgent 采用相似的有限工作区约束，但对象是长文档证据流：顺序读取文本块，用普通 token 写出新记忆并覆盖旧记忆，读完后根据问题和最终记忆回答。训练通过多段独立上下文的强化学习，把最终答案的奖励传到中间记忆更新。与 MEM1 的交互式工具环境相比，它更集中地研究大量输入经过有限工作区后，还能留下多少回答依据。两者都把可读文本作为状态，模型内部的隐状态载体将在载体章另行分析。[29][28]

MemAgent 的消融显示：直接套用分块覆盖流程，在 LongBench-QA 上只有很小收益，部分设置下降；加入强化学习后才出现稳定改善。其证据位置实验还将关键内容放在开头、结尾或中部，检验后续覆盖是否冲掉前面的信息。这说明可扩展的循环框架只是第一步，保留哪些信息需要与任务反馈共同学习。[29]

展开：两种受训状态管理的协议差异

MEM1 从 Qwen2.5-7B Base 出发，以 PPO 训练，评估内部检索 QA、开放网络 QA 和 WebShop；训练和测试均使用会裁剪上下文的交互流程。MemAgent 采用 Qwen2.5 的 7B/14B Instruct 与 multi-conversation DAPO，默认记忆为 1,024 token、文本块为 5,000 token，在约 8K 工作窗口中顺序处理长输入。其超长输入结果主要回答长度外推问题；MEM1 的组合任务回答多轮交互外推问题。长度、目标数和环境变化应分别报告。

5. 在状态、回读与计算之间选择

上述工作形成了三种可组合的选择。对于细节随时可能再次变得重要的任务，采用 MemGPT、ReadAgent 式的可回读工作区；对于具有清楚阶段边界的任务，采用 HiAgent 式的子目标摘要；对于能够收集任务奖励、需要大量重复运行的环境，训练 MEM1、MemAgent 式的状态更新策略。实际系统可以先保留原始轨迹，再逐步学习把哪些信息常驻、哪些信息按需取回。

选择时，最值得测量的是同一任务在不同历史长度下的完成率、状态中关键约束的保留情况，以及回读带来的总成本。更短的提示有价值，是因为它减少重复处理并帮助行动；当恢复遗漏信息需要大量工具调用时，省下的 token 应与新增回读一起计量。学习过程如何获得可靠反馈，在记忆管理学习中继续展开。

工作状态随当前任务结束而完成使命，其中一部分信息却应继续服务下一次会话。例如，排障过程中确认的接口 v2 生效日期，值得进入项目知识库；“已经修改了两个调用方”则留在本次任务轨迹。接下来的问题是：这些被长期保留的事实，怎样组织、取证，并随项目变化及时修订。
