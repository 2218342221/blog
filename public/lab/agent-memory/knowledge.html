CHAPTER 04 / 事实与证据

把长期历史，
变成可更新的证据

比较记忆单元、动态关联、时序与层次结构，理解写入和读取如何共同决定效果。

状态 · 事实 · 经验
跨会话知识记忆，要同时提供容易找到的事实和能够追查的依据，并让它们随新信息保持有效。继续代码项目的自拟场景：Agent 上次记住“项目默认使用接口 v1”，本次发现 v2 已发布但部分服务仍在迁移。它需要知道这条规则适用于哪个服务、从何时生效、依据是什么；一个相似度很高的旧摘要，往往只解决了其中一部分问题。
证据与访问表示形成记忆单元建立关联维护有效性组织读取收益与成本

1. 原始证据与访问表示，承担两种职责

从历史对话、工具输出和文档中直接检索原始片段，是这条研究线的起点。原文保留了措辞、条件和上下文，但也包含重复表述、指代和交错主题。为了让未来的问题更容易找到答案，记忆系统会额外生成摘要、事实、实体关系和索引。这些派生表示的价值，是让原始信息更容易被寻址和组合。[1][15]

RMM 对这种分工给出了清楚实现：每个记忆条目保存 topic summary 与 raw dialogue，主题摘要作为检索键，关联的原始对话保留事实依据。会话结束后，系统抽取不同主题，对新旧相关记忆进行合并或追加；回答时检索主题，再使用关联内容。代码项目中，“接口鉴权方式”可以成为紧凑的访问入口，而具体版本限制仍应能回到对应文档和讨论。[15]

ReadAgent 的 gist 和 HippoRAG 2 的图也体现了相似分工：一个引导展开原始页面，一个引导选出原始段落。由此可见，重要的设计问题是派生表示如何指向证据。选择图、树或向量索引，应由实际查询决定：精确接口名需要词法匹配，跨模块依赖需要关联，历史版本问题需要时间范围。[54][11]

2. 先形成能独立理解的记忆单元

记录“这个已经改好了”几乎没有长期价值；记录“服务 A 的鉴权接口在 v2 中改用短期令牌”，才具有清楚主体和条件。SimpleMem 在写入时进行指代消解、相对日期规范化和事实拆分，再建立语义、关键词与结构化元数据索引。它还在当前会话内合并相关片段，让分散条件形成可共同读取的条目。例如，服务名、接口版本和迁移日期可以一起构成事实，而非分别等待读取阶段重新拼接。[57]

粒度应当与信息结构对齐。RMM 按主题抽取并关联原始对话；LightMem 在预压缩后按主题组织交互，用缓冲批量生成记忆；SimpleMem 从滑动窗口中提取能够独立解释的单元。它们分别强调跨轮主题完整性、构建吞吐与语义消歧。主题可以跨越多轮对话，一个会话也可以包含多个主题，固定 turn/session 边界因此只是输入边界。[15][62][57]

RMM 在随机抽取的 LongMemEval 样本上比较 turn、session、两者混合和主题组织，主题组织同时改善了检索与问答；简单混合不同粒度反而引入更多候选噪声。SimpleMem 的消融则显示，移除包含指代和时间规范化的语义压缩后，时间推理 F1 明显下降。两类证据共同支持一个认识：形成完整、可解释的信息单位，是有效压缩的重要条件。[15][57]

展开：粒度与消歧的实验依据

RMM §8.5 的粒度分析使用 100 个 LongMemEval 样本、GTE 检索器和 Gemini-1.5-Flash；其“最佳粒度”是每个样本从 turn/session 中选择较优者的参照。SimpleMem Table 5 使用 GPT-4.1-mini：移除整套语义压缩后，Temporal F1 从 58.62 降到 25.40。该移除同时改变抽取、消歧与表示，支持的是整套写入表示的作用。LightMem §5.4 的主题分段消融也显示，不分段略省计算，却降低下游 QA 准确率。

3. 关联用于写入理解，还是用于读取推理

当答案需要连接多条记录时，孤立条目的相似度检索开始受到限制。A-MEM 在新笔记到来时，先通过向量检索找到邻近旧笔记，再让 LLM 判断关系，并决定是否更新旧笔记的上下文描述、关键词和标签。新信息不仅增加一个节点，也改变旧信息的可解释方式。它适合说明写入时的整合：例如新迁移文档可能让早先的错误日志获得更明确的版本背景。[12]

HippoRAG 2 更集中于读取时的关联。它用抽取出的关系构建图，将原始 passage 也纳入图；问题先匹配关系三元组和段落，再用个性化 PageRank 沿关系传播，取出相关原文。早期 HippoRAG 主要以实体进入图，实体名可能省略问题中的条件。第二版增加 query-to-triple 和 passage 节点，让关系的语义与原文语境共同决定搜索方向。[10][11]

这个差异能被消融直接说明：HippoRAG 2 在三个多跳 QA 数据集上，完整方法的平均 passage Recall@5 为 87.1，移除 passage 节点后为 81.0；改回实体识别后匹配节点，降至 74.6。A-MEM 则在长期对话 QA 中发现，链接生成和已有笔记更新分别带来增益。前者说明图搜索需要保留语境，后者说明记忆进入系统时的整合有价值。两者的共同问题是：一条关系究竟帮助系统找到了哪些原本难以共同获得的证据。[11][12]

另一种关联是跨记录的层级概括。MemTree 在写入时沿语义相近的分支插入，并更新祖先摘要，让同一批记录同时具有细节与主题层表示。它的主要读取方式将各层节点放在一起按相似度选择，并非必须从根逐层走到叶子。相较于 HippoRAG 2 用图连接原始段落，树的价值在于形成多种概括粒度：问“这次调用失败在哪里”需要细节，问“项目迁移反复出现哪些问题”则可能需要跨记录的共同主题。组织结构与读取算法仍是两个独立选择。[59][11]

展开：如何阅读图方法的增益

HippoRAG 2 Table 4 的三组任务是 MuSiQue、2Wiki 和 HotpotQA，指标是原始段落召回；无候选过滤的平均值仍有 86.4，表明该实验中主要贡献来自上下文匹配和 passage 融合。A-MEM Table 3 在 GPT-4o-mini 上进行消融，移除链接与更新、仅移除更新、完整系统的 MultiHop F1 依次为 9.65、21.35、27.02。这些实验检验不同阶段和指标，适合解释机制，不宜排列为统一排名。

4. 让事实保持有效：时间、主体与证据身份

长期记忆还要表达变化。“接口 v2 从周一启用”可能周三才写入知识库；“项目已迁移”可能只适用于服务 A。查询当前状态、事故发生时的状态、当时系统已知的状态，分别需要不同时间和范围。Zep/Graphiti 将事实的有效时间与系统记录时间分开，保留实体关系及来源事件；新事实与旧关系发生时间重叠的冲突时，更新旧关系的失效时间，以同时支持当前查询和历史追溯。[33]

AriGraph 把更新问题放进可交互环境：用语义三元组表示当前世界，用情节节点保存当时的完整观察，新观察到来后修订失效关系。在文本化游戏中，“物品现在在哪里”更依赖语义状态，“配方具体怎么写”更依赖完整观察。它连接了任务内状态与可回溯事实，也说明保留历史不等于把所有历史状态都当成当前事实。[60]

Hindsight 进一步区分记录的语义身份：外部世界事实、Agent 自身经历、主观观点和由多条事实归纳出的实体概况。这个分工有助于解释为何“用户说服务 A 已升级”“Agent 建议升级”和“Agent 推测已升级”需要不同处理。它用实体与时间组织事实，多路检索后重排，再把证据交给回答与反思层。归纳概况可以提高读取效率，底层事实则提供追查和修订的依据。[56]

在 Zep 的 LongMemEval 结果中，时间推理、跨会话和偏好查询是收益较明显的类别；知识更新的收益又随回答模型变化。Hindsight 也在 LongMemEval 的时间、多会话和知识更新问题上报告较强表现。这些结果显示，结构化上下文能够帮助长期事实使用；它们同时提示，时间信息必须以回答模型能够正确使用的形式交付。工程中的版本过滤、冲突修订和来源追踪将在生产章继续落到具体约束。[33][56]

5. 从找到相似记录，到组成问题需要的证据

一次读取往往同时需要几种匹配能力：精确名称、语义近义、时间限制和关联实体。SimpleMem 根据问题生成语义、词法与结构化查询，动态决定读取范围，再对结果按条目身份去重；Hindsight 将多路检索、融合与神经重排组合，并允许调用者指定输出 token 预算与检索努力。这样，“查询一个接口名”和“解释三次版本迁移”可以获得不同的搜索深度。[57][56]

读取还可以从单次召回扩展为有目的的信息搜集：当前结果是否已覆盖问题的全部条件，是否需要补充时间、关联实体或原文细节，都可以成为下一次查询的依据。SimpleMem 移除意图感知读取后的下降，支持了根据问题组织证据的价值。让这种选择进一步随反馈适配，则进入管理学习的范围：RMM 训练轻量重排器，MemSifter 训练负责选择历史的代理模型。它们的监督来源与优化对象将在下一章组中比较。[57][15][68]

6. 构建记忆的价值，取决于预算和复用

复杂组织需要付出摄入、抽取和维护成本。LightMem 把同步更新改成先追加、后离线整理，并通过预压缩和主题缓冲减少构建调用；SimpleMem 在会话写入阶段即时合并相关事实。前者将更多整理工作移出在线路径，后者尽早压缩碎片。选择取决于新信息多久需要可见、同一份历史将被读取多少次，以及系统愿意为未来读取预先投入多少计算。[62][57]

LightMem 的独立复现提供了关键校准：固定构建后的记忆库和生成设置，更换检索器就会显著改变准确率；与直接检索原始用户 turn 比较时，构建记忆的优势主要出现在紧回答预算。约 330 token 的条件下，它在 11 个检索器中胜出 8 个，平均提高 5.5 个百分点；预算增到约 935 token 时，平均优势消失。紧凑条目让有限窗口容纳更多证据，但原文在预算充足时保留更多细节。[69]

因此，跨会话知识记忆应把写入表示、检索器、回答预算和维护成本一起设计。一套有解释力的比较，应同时保留强原文检索基线、构建表示，以及能够排除检索遗漏的证据条件。保留原始记录，再用摘要、关系和时间结构提供多种访问方式，是贯穿本章的系统思路。它让知识随着项目演进持续可用；当 Agent 进一步从多次排障中提炼“怎样更快定位版本问题”，研究对象就从事实延续转向了跨任务经验与技能。
